## 这张图只确定四条逻辑边界

1. **只有两类外部来源**：Min 是市场原始数据和字段边界；论文/研报由研究者手动补充。这里的“不循环”仅指不会因为 Research 的一次成功/失败而自动重写这两个库；不意味着市场新数据或新论文永远不能加入。
2. **另外两库是真正循环的状态**：Daily 的中间日频特征被不断复用、扩充；**知识库本身就是 Alpha 成功/失败经验库**，包括候选、真实实验记录、反馈与父子谱系。**没有第五个 Alpha 库**。四库都能成为后续 Research 的输入，但只有 Daily 与知识库接受 Research 的研究反馈。
3. **Daily 的形成不限于初始准备阶段**：一次 Alpha 探索即使整体不成功，也可能发现一种有用的底层计算表达式；只要具备数据可得性、正确时点、明确含义和复用价值，就**可以考虑**作为 Daily 中间特征沉淀。反过来，Alpha 得分好也不自动把整条 Alpha 晋升为基础 Daily 特征。图中两个分流箭头是**两类判定，而非每次必经两道关卡**。
4. **21 个金融 Agent 与遗传进化都在 Research Loop 中**：21 是专业研究角色，不据此强定“先一批 Agent 建 Daily、再一批 Agent 挖 Alpha”或要求每轮走固定顺序。遗传循环在每次候选检查/评价之外选父代和创建子代；Mutation / Crossover 可由程序或 AI 实现，尚未定。**遗传种群不是持久知识库，也不是最终因子池**。

## 仍需一起设计，而非假定已决定

- **21 专题角色如何调度？** 让同一批 Agent 按任务需要生成 Daily 与 Alpha，还是安排专职特征构建角色，或确实拆为两段？目前三种都只是候选。
- **Daily 入库标准是什么？** 需区分计算正确、时间可用、能重复复用，与 Alpha 是否有效；还要记录定义/依赖/计算版本，避免循环依赖（系统反馈可循环，单个特征的计算依赖不应自我循环）。
- **知识库的反馈怎样用于生成？** 直接引导、先自主构思再去重、遗传父代筛选，这些作用不同，不提前定具体 Prompt/检索工具与比例。

**特别提醒**：“挂单极性”只是解释中间特征的例子；若只有分钟 O/C/V/VWAP，无法从中唯一恢复真实订单/挂单极性。原文金融假设、我们自己的实验记录和实际数据可得性仍须分开。
