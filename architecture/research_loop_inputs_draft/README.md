### 这张图表达的结构

**四库并列输入，并不等于四库内容完全相同或每轮都必须全读。** 论文库存来源、金融知识库存核验过的定义/证据、Min 库存可用分钟字段及数据、Daily 库存已实际计算并可复用的日度中间特征。统一接口只是访问边界，不预设向量 RAG、智能检索 Agent 或数据库选型。

**两个业务阶段，不等于必须先后跑两轮 21 Agent。** 第一阶段是按需补齐 Daily 特征的“准备/物化”工作：由特征构建 Agent（仅表示职责，人数和实现尚未决定）提出计算定义，经字段检查后用程序执行并缓存；已有 Daily 可直接复用。第二阶段由 **21 个金融专题 Agent** 利用四路输入自主寻找 Alpha 的假设、变换、时序关系与代码。某位 Agent 发现缺少 Daily 中间量，可以再发请求给第一阶段，二者不必每次整批顺序运行。

**Alpha 候选不是 Daily 中间量的同义词。** 例如“某分钟挂单极性 → 当天均值”属于中间特征；“过去五天的均值进一步变化、与其他特征互动”仍只是一种待评价的 Alpha 候选。由研究验证支持其有用性，不是由命名决定。挂单极性需要真实委托/订单字段；不能从现有暂定的分钟 O/C/V/VWAP 唯一还原。

**同一个 Research Loop 内有两条不同的回流路径：**
- **研究反馈**：所有实验都进入 Alpha 经验库，21 Agent 可按需取历史成败、失败原因和已试方向，避免机械重复；是否生成前检索还是生成后去重，尚未定。
- **遗传进化外循环**：依据历史候选、真实适应度和父子谱系选父代、变异/交叉，再进入**同一个**代码检查与 Evaluator。Mutation/Crossover 是操作名称；可以由程序、LLM 或二者结合实现，目前没有定稿。遗传种群、持久 Alpha 经验库和最终入选的因子池不是同一对象。

## 暂不拍板但必须区分的问题

1. **“知识库”究竟指什么？** 本草图暂将它用作“从论文/研报中整理的客观金融知识”，因此四个并列输入 + 一个动态 Alpha 经验库，是**五类逻辑记录域**，不代表五个物理数据库。如果研究者原意的“知识库”就是**成功/失败因子经验库**，它应直接和 Alpha 经验库合一；原文抽取知识保留为论文库的可检索部分，便可改为**四个逻辑库总数**。两种命名不能混用，待明确后再定主图。
2. **成功因子的日度值要不要写回 Daily？** 可以考虑将其数值作为独立的派生缓存，但 Alpha 公式、实验与是否通过标准归 Alpha 经验库；不因“也是日频数字”就自动提升为通用中间 Daily 特征。暂不画自动回写箭头。
3. **是否所有 21 Agent 同时处理、如何分工与调度、Alpha 最终晋级标准是什么？** 目前只保留“21 金融专题探索 + 统一质量评测 + 进化”职责，不指定轮数、Prompt、调度算法或物理部署。
4. **如何检索不扼杀独立构思？** 统一接口只是逻辑边界，不意味着每个 Agent 开始前必须被固定 Top-K 提示“引导”；此前独立构思后查重的经验必须保留为可选工作方式。
