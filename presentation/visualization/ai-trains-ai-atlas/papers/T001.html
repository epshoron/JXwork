T001 · METHOD IN CONTEXT

Promptbreeder

让任务指令 P 与“怎样修改指令”的 M 一起演化；外部任务评分决定保留谁，模型权重始终固定。

Prompt + 改写 Prompt优化对象可核查作者结果 ≠ 独立复现
T001
01 / EXECUTION LOOP

原文机制如何流动？

实线按运行顺序；虚线回到下一次探索。每个方框代表实际输入、动作或检查，不意味着所有步骤都是模型训练。

真正更新的对象：更新的是 P/M 文本、示例与进化种群；任务评分准则和基础 LLM 参数不随搜索自改。
02 / CONCRETE EXAMPLE

用一个例子看懂

假设原始 P 只要求“回答推理题”。M 教 LLM 强调分步骤检查，新的 P 在样本题上得分提高，就进入种群；某些操作还会用固定元指令 H 改写 M。此例用于说明 P/M/H 作用分工，不是论文的逐字 Prompt。

03 / DISTINCTIVE MECHANISMS

三个关键实现位置

TD001 · 双层候选

进化单位同时带任务 Prompt P 与变异 Prompt M；M 的更新会改变以后产生 P 的方式。

TD002 · 从成功轨迹反推

不仅随机变换措辞，还能根据正确解答、种群经验反推更有用的任务指令与示例。

选择方式

多个候选在训练任务上真实得分，再经二元锦标赛淘汰；不会每次评测就对 LLM 微调。

04 / RELATIONSHIPS

与其他路线怎么区分？

与 T002 同属外部 Prompt 优化，但 T001 还演化“改写 Prompt 的方法”M；T002 更强调有诊断文字的执行轨迹与逐样例 Pareto 选择。

05 / CLAIMS & LIMITS

效果与证据边界

作者报告：原文同表 PaLM 2-L / GSM8K 零样本：Promptbreeder 83.9%，OPRO 80.2%；仅是该设置下的准确率，不能推成生产 Agent 收益。

不要扩大解释：依赖预设变异操作与固定的高层指令 H；未展示 LLM 权重自训练，也未独立复现。
