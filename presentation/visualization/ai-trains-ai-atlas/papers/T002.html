T002 · METHOD IN CONTEXT

GEPA

从执行/评价轨迹中找模块级错误，反思式改写一个模块 Prompt，再以逐样例 Pareto 策略保留互补候选。

反思 · Pareto · Prompt优化对象可核查作者结果 ≠ 独立复现
T002
01 / EXECUTION LOOP

原文机制如何流动？

实线按运行顺序；虚线回到下一次探索。每个方框代表实际输入、动作或检查，不意味着所有步骤都是模型训练。

真正更新的对象：实际更新的是完整候选 Prompt 套件中一个或多个模块的文字；模型权重与基本控制流保持固定。
02 / CONCRETE EXAMPLE

用一个例子看懂

问答 Agent 连续两次搜索，却反复搜同一实体。Reflection LLM 阅读输入输出与工具检索结果，发现第二跳应关注“还缺什么”，于是修改第二跳查询模块的 Prompt；新版本需在同一小批量任务上超过父代才纳入池。

03 / DISTINCTIVE MECHANISMS

三个关键实现位置

TD003 · Trace 反思

将执行轨迹、评测数字和文字诊断合并为可操作的修改依据，局部替换选定模块 Prompt。

TD004 · 逐样例 Pareto

保留在不同具体题目上有优势的候选，避免只围着全局平均第一名搜索。

TD005 · 可选谱系合并

对不同家系互补模块的 Prompt 进行结构化合并；并非纯文本随机拼接，且不是总能更好。

04 / RELATIONSHIPS

与其他路线怎么区分？

与 T006 一样用真实运行反馈，但 GEPA 是一个通用 Prompt 搜索算法；T006 是评测编程 Agent 改科学模型的基准环境。两篇不是算法与工程复现的对应关系。

05 / CLAIMS & LIMITS

效果与证据边界

作者报告：作者报告 Qwen3-8B 六任务聚合 GEPA 54.85、GRPO 48.91；GEPA+Merge 52.40。任务和训练预算受限，不代表所有 RL 都弱于 Prompt 搜索。

不要扩大解释：部分任务 GRPO 更优；绝大多数 rollout 用在候选验证，反思模型另有成本；未独立复现。
