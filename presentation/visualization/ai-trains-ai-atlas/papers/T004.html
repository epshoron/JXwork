ADAS · Meta Agent Search

T004
01 / EXECUTION LOOP

原文机制如何流动？

实线按运行顺序；虚线回到下一次探索。每个方框代表实际输入、动作或检查，不意味着所有步骤都是模型训练。

真正更新的对象：更新的是下层 Agent 的 Python 设计及档案，底层生成模型、Meta Agent 模型参数未训练。
02 / CONCRETE EXAMPLE

用一个例子看懂

原先下层 Agent 一次调用模型直接答题。Meta Agent 生成 forward(task)：先让多个角色独立作答，再调用评审模块汇总。实验系统在验证集运行这个新程序，失败时尝试修复，通过后把代码和得分记入档案。

03 / DISTINCTIVE MECHANISMS

三个关键实现位置

TD010 · 程序级搜索

可修改整个 Agent 的可执行 Python 调度结构，不局限于自然语言 Prompt。

TD011 · 设计档案回流

保留旧 Agent 的程序、评价与设计作为下一次 Meta Agent 的 stepping stones。

反思与修复

写出候选后有设计反思与运行时修复，两者都不等于强化学习。

04 / RELATIONSHIPS

与其他路线怎么区分？

T001/T002 搜索提示文字，T004 搜索 Agent 的控制流程代码；T006 则让现成 Agent 改科学研究任务的模型代码，研究对象的层级不同。

05 / CLAIMS & LIMITS

效果与证据边界

作者报告：原文 Table 1：DROP F1 79.4、MGSM 准确率 53.4，优于表内所列相应基线；是独立目标域实验，不是跨域统一百分比收益。

不要扩大解释：模型生成的 Python 需要隔离执行；论文没有证明部署后 Agent 可安全持续在线自我改写；未独立复现。
