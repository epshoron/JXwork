Agent4Sci

标准化科学 ML 任务、预算及封存测试集，让现成编程 Agent 自主改科学模型代码并做实验，最终独立评分与审计。

T006
01 / EXECUTION LOOP

原文机制如何流动？

实线按运行顺序；虚线回到下一次探索。每个方框代表实际输入、动作或检查，不意味着所有步骤都是模型训练。

真正更新的对象：改动的是科学任务模型的代码、参数和实验产物；编程 Agent 的 LLM 参数与 Skills 内容不因本实验自动更新。
02 / CONCRETE EXAMPLE

用一个例子看懂

研究 Agent 阅读某科学预测模型论文与原代码，提出修改网络或损失函数，利用 GPU 训练后看验证指标，再决定继续尝试还是提交。最终才由独立评价 Agent 访问 Test；审计 Agent 检查是否利用测试信息或操纵得分。

03 / DISTINCTIVE MECHANISMS

三个关键实现位置

实验环境而非优化器

论文主要贡献对象是评测平台与研究 Agent 轨迹分析，而非发明用于搜索 Prompt 的新算法。

三种固定 Skills

Research、Experiment、Checklist 是研究者预先编写、作为开关干预的流程指导；没有由系统自动改写这些 Skills。

训练/验证/测试隔离

Agent 可反复训练科学任务模型，却不能用封存 Test 为每轮想法打分；审计与最终评测独立。

04 / RELATIONSHIPS

与其他路线怎么区分？

与 T002 重合在运行→反馈→反思的普遍闭环；但 T002 真正交付改进 Prompt，T006 交付科学模型、测试分数与审计。T006 没有采用 GEPA 的 D_feedback/D_pareto / 逐样例选父代，不能称 T002 的工程实现。

05 / CLAIMS & LIMITS

效果与证据边界

作者报告：作者报告 Opus 平均相对基线改善 10.4%，加固定 Skills 后 20.1%；Codex 4.4% → 8.1%。是不同科学 benchmark 的相对改进聚合，不能与 GEPA 的任务分数横向比较。

不要扩大解释：现有档案已核对论文摘要/公开正文材料但未逐页独立复核上传 PDF；原始 Agent 的研究能力和定量改善不能等同新的科学理论发现，贡献/不足未审批。
