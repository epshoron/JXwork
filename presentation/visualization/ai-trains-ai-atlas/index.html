05 / RELATIONS & FRICTIONS

共性、互补与不能混淆的地方

以下“冲突”指优化对象或证据口径不同，不意味着论文之间已被实证证明互相否定。

T001 × T002 · 同属 Prompt 搜索

改写规则 vs Trace 反思

T001 同时进化任务 Prompt P 与变异 Prompt M；T002 从错误轨迹定向改一个模块，Pareto 保留各有擅长的候选。

T002 × T003 · Trace 的两种用法

反馈文本 vs 参数梯度

GEPA 的执行轨迹导出新 Prompt；Lightning 将多次 LLM 调用转为可训练 transition，最终更新模型权重。

T003 × T005 · 两种权重训练

外部奖励 vs 自评偏好

T003 依据环境/工具轨迹的任务回报；T005 让模型自己打分形成偏好对。Judge 可信度面临不同问题。

T002 × T004 · 搜索空间不同

Prompt 文字 vs Agent 程序结构

GEPA 保持主要控制流固定；ADAS 直接编写新 forward(task)，可变化角色组织和调用结构。

T002 × T006 · 重点比较

不是 GEPA 的工程实现

确实都执行、反思、再尝试，但 GEPA 明确优化 Prompt、按 Pareto 选择；Agent4Sci 评测现成编程 Agent 改科学模型的能力，没有采用 GEPA 的 D_feedback/D_pareto 规则，也没有自动演化那三种 Skills。

T005 × T006 · 评价隔离

自我评判 vs 外部封存测试

T005 利用当前模型的 Judge 评价数据训练自身；T006 只允许 Validation 反馈轮内研究，Test 和 Audit 在研究结束后独立进行。两者任务不同，不能直接比较“谁更可靠”。
