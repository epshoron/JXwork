P002
01 / HOW IT RUNS

系统怎么运行？

从输入走到真正可检查的输出；下方虚线提醒这不是单向流水线，而是存在反馈。

反馈到底更新什么：优秀父代与精英得以保留，LLM 修改或组合代码后重新进入质量检查；成败经验回写提示词
02 / MAKE IT CONCRETE

用一个例子理解

把候选代码看成一个“种群”。先按 IC、RankIC 等挑出较好的父代，再让 LLM 对代码做局部修改，或把两个父代的思路组合为新候选。

03 / IMPORTANT MECHANISMS

三个关键点

D006 · ②构思

21 个金融主题角色 + 五种指导方式

七类研究主题细分为 21 个 Agent 角色；五种不同提示引导改变研究想法的覆盖范围。

D007 · ③生成 / ⑥保留

代码级进化（同一组机制的两个落点）

LLM 对 Python 因子代码执行变异、交叉；依据 Fitness 选择父代并保留精英，使下一代继续探索。

反馈 · 实现差异

普通的经验回流

成功与失败案例写回生成提示，有价值但不单独视作特别的学习算法。

04 / COMPARE

和其他论文区别在哪？

它与 P008 都有“进化”，但 P002 的更新对象是因子代码种群；P008 还通过强化学习训练围绕种子连续改进的 LLM 策略。

实际被更新的对象：Python 因子代码、种群、成败案例提示；不更新 LLM 权重
05 / EVIDENCE BOUNDARY

哪些结论需要保留边界？

论文在不同市场报告历史回测结果；不同主题 Agent 是否总能带来低相关的新因子仍值得检验。这里不把“21 个 Agent”理解为 21 个独立训练模型。
