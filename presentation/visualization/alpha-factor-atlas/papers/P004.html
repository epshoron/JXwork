01 / HOW IT RUNS

系统怎么运行？

从输入走到真正可检查的输出；下方虚线提醒这不是单向流水线，而是存在反馈。

反馈到底更新什么：MCTS 回传访问/价值统计 → 决定下一轮扩展路径；Alpha Zoo → FSA 高频子树负向约束 → LLM
02 / MAKE IT CONCRETE

用一个例子理解

假设某候选 IC 好但换手率高。MCTS 不只是要求“再试一次”，而是选择这个研究分支，并把换手率弱项作为下一步修改的方向。

03 / IMPORTANT MECHANISMS

三个关键点

D010 · ⑤ + 反馈

MCTS 树搜索与多维反馈

UCT 平衡探索和利用；多维评价决定待优化方向，评分回传给搜索树，从而改变未来分支选择。

D011 · ③生成

FSA：频繁子树规避

从已留存 Alpha Zoo 中挖掘高频 AST 子结构，将其作为下轮生成时的负向约束，减少相似公式反复出现。

⑥保留 · 实现差异

Alpha Zoo 的配套作用

保存达标候选，既供模型组合使用，也提供 FSA 观察高频模式的样本。

04 / COMPARE

和其他论文区别在哪？

P002 是种群进化与父代选择；P004 则维护有访问次数与价值统计的搜索树。P003 的 AST 机制是相似性惩罚，不等于 FSA。

实际被更新的对象：MCTS 搜索树节点价值、下一轮搜索方向与 Alpha Zoo；不更新 LLM 权重
05 / EVIDENCE BOUNDARY

哪些结论需要保留边界？
