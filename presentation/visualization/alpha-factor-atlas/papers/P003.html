P003
01 / HOW IT RUNS

系统怎么运行？

从输入走到真正可检查的输出；下方虚线提醒这不是单向流水线，而是存在反馈。

反馈到底更新什么：质量不合格 → 重新修改表达式；评价结果 → 返回构思/生成 Agent，并积累经验
02 / MAKE IT CONCRETE

用一个例子理解

即便一个公式能运行，仍可能过度像 Alpha Zoo 中已有公式，或实际含义与最初金融假设不一致；P003 希望在生成过程中约束这两类问题。

03 / IMPORTANT MECHANISMS

三个关键点

D008 · ④约束

AST 结构原创性约束

比较生成公式与已有 Alpha Zoo 的 AST 公共结构，对过高的表达式相似度施加惩罚；这是结构新颖性，不自动等于预测信息独立。

D009 · ④约束

假设—描述—公式一致性

检查自然语言金融假设、因子解释与真正数学表达式是否相互对应，减少“说的”和“算的”两套逻辑。

③⑤ · 实现差异

Factor 与 Eval 的具体分工

Factor Agent 借助符号运算符生成，Eval Agent 组织评价与反馈。这两处有实现区别，但无需独立强调为创新。

04 / COMPARE

和其他论文区别在哪？

相对 P004：P003 是针对候选与历史公式施加结构相似性惩罚；P004 从候选库统计高频子树，提前限制后续公式生成。

实际被更新的对象：候选公式、约束分数及外部经验；无 LLM 参数更新证据
05 / EVIDENCE BOUNDARY

哪些结论需要保留边界？

作者报告约束组合使有效因子比例从 0.16 提高至 0.29；这不能单独证明每项约束的独立因果效应。
