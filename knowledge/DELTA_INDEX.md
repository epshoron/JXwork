## P002 已审特色与待审内容

- **已获研究者确认**：[D006](deltas/D006_domain_guidance.md)：21 个金融主题 Agent + 五类 Prompt 引导的专业化搜索；对应风险为不同 Agent 产生的因子可能高度同质，需要独立因子增量实验（目前没有证实发生）。
- **已获研究者确认**：[D007](deltas/D007_code_evolution.md)：Python 因子代码的父代选择、Mutation/Crossover、精英保留与多代搜索。不是首创遗传算子；没有经过审批的专属缺点，不硬凑。
- **尚待讨论**：成败 Prompt 反馈是否相比已有研究构成足够独特的创新 Delta。
- **背景**：普通职责分工、时间切分及费用回测不计为本论文的独特创新机制。

## P003 已审特色：与既有机制去重（2026-10-21）

- **新入库的两项具体控制**：[D008](deltas/D008_ast_originality_penalty.md) 的**候选对 Alpha Zoo 最大公共子树惩罚**；[D009](deltas/D009_hypothesis_factor_alignment.md) 的**假设—描述—公式双层评分**。二者为**已讨论认可的特化机制**，不是已证实学术首创。
- **不重复建卡**：Idea/Factor/Eval 反馈循环、角色分工、外部知识记忆沿用 D001/D003/D004 作为架构背景；AST 符号组装与公式复杂度不强行单列创新。与 D002 正向公式先验、D006 主题多样化、P004 FSA 的**作用点**不同；P004 创新评价仍待该篇审批。
- **具体缺口**：结构新≠信号新、Eq. 8 符号方向、约束组合消融难以隔离原创性作用；只在 [P003 IDEAS](../papers/P003/IDEAS.md) 集中描述，不生成重复通用 OOS/交易成本 Delta。

## 贡献及不足的审批门槛

每篇先画架构、理解原文；**创新点、特化不足和我们的推论必须先在 LLM 对话中逐项提出，经研究者明确拍板，才更新对应已批准知识卡**。研究 Agent 不得为了凑数量录入一般 OOS、成本、市场变化或套话式过拟合；风险要明确关联某篇的独特设计及可检验证据。完整规范见 [RESEARCH_WRITING_STANDARD.md](../RESEARCH_WRITING_STANDARD.md)。

## 以后比较新论文时怎么用

- **存在完全同等机制**：引用基础机制记录或已批准的旧 Delta；没有特化增量就不创建新 Delta。
- **同一机制但具体改动**：先在对话说明改动与证据；**获批后**在旧卡追加变体（例如提示反馈变为持久记忆），不能把所有变体都称作创新。
- **真正出现不同机制**：**先在对话中给出特化差异及证据，获研究者批准后**才新建卡，并与最相近旧机制对比。
- **证据无法区分**：标待核，不以“看起来更新潮”强行添加。

**项目级目标**：随论文积累，逐渐形成可比较的模块库/机制图谱。研究者确认后，才根据既有机制、论文实证和缺口推导我们的创新方向；当前主要任务仍是理解文献本身。
