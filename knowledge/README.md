# JXwork · Delta 知识库（跨论文机制数据库）

**审核原则（2026-10-21）**：D002（P001 公式先验）与 D006（P002 金融专业主题 + 多样化提示）及其特化风险已获研究者讨论认可；但创新程度和实际风险尚需证据核查。D001/D003/D004 为背景对照，D005 为通用评价规范；代码级种群进化 D007 已获研究者认可；**代码灵活导致验证困难**的缺点提议未通过，不另立相应缺点。**先审后入库**。

**目的**：不是重新存放逐篇论文综述，而是把每篇真正读懂的论文拆成**可对照的技术机制/知识单元**。未来研究 P00X 时，先对照现有知识，辨别它到底新增了什么；从积累的共性、差异和未解问题里，逐步形成真正的研究地图。

## 三个“新”必须分别判断

1. **新进入本项目知识库（KB-first）**：某项机制第一次被我们的数据库记录。**P001 是第一篇，所以它涉及的主要机制都属于 KB-first。**
2. **相对此前论文有增量（Paper Delta）**：新论文的**特化机制**相对已有卡片有可证实的搜索、先验、反馈或知识更新差异。普通 OOS、成本或常规 Agent 分工不是创新 Delta。可以是已有机制的变体，不必硬凑一个新名字。
3. **学术原创（Literature Novelty）**：经过相关前作对照，才有资格判断“论文新发明了什么”。**KB-first 绝不等于首次学术提出**。如 P001 的双循环已见于 QuantAgent 2024。

这三层标记必须并存，不可替换。

## 结构

- [DELTA_INDEX.md](DELTA_INDEX.md)：所有已登记机制的总索引、首次观察来源、学术新颖性边界。
- [deltas/](deltas/)：每一个独立机制的证据卡（D001、D002…），记录定义、来源、变体、客观缺口及后续修订。
- [../papers/](../papers/)：论文档案（原文来源、系统图、作者贡献、评价以及我们的候选研究想法）。
- [../synthesis/](../synthesis/)：跨论文比较成熟后、研究者认可的综合研究结论；知识卡不是完整研究地图。

## 新论文的 Delta 判定算法（人工 + 研究 Agent）

1. 查 `papers/INDEX.md`，认领论文，**先理解论文大架构和真实原文证据**。
2. 提取几个关键机制而非标题关键词，按六个字段比对：**研究任务、先验/输入、生成或搜索控制、反馈与更新对象、验证方式、记忆/协作结构**。
3. **先在对话里提出候选创新/不足并获研究者逐项审批**，才能正式认定为新 Delta。与 D001…逐条比：`已有`（same）、`具体变体`（variant）、`新机制`（new）、`证据不足`（uncertain）。已有内容不重复开卡；变体在现有卡新增 `P00X` 与差异证据；真正新机制才新建 D00X。
4. **单独核验与更早原始研究的关系**。不要把“相比我们数据库此前论文的新变化”自动写成世界范围首创。
5. 记录明确对照：**前作做法 → 本篇做法 → 变化发生在哪一步 → 该变化是否经实验证明有用 → 尚有什么风险**。没有实证就标明“设计差异，效果未验证”。
6. 不因某论文的名称、性能数字、通用评价口径或重复包装就创建新机制。研究者可在任何时候修正合并卡片，保留来源和旧判断记录。

## 统一卡片字段

`ID / 名称 / 解决什么 / 输入输出 / 控制与反馈对象 / P001首次入库证据 / 与更早论文比较 / 已观察的不同实现 / 未解决的边界 / 证据状态 / 相关论文链接`。

P001 是初始研究基线，**D002 是经讨论确认的重点机制**；P002 的 D006、D007 两项具体特色机制已获研究者认可；仅 D006 伴随一项获批的、尚未实证的同质化风险。不得将知识卡存在等同于已获审批的原创结论。

**数据安全**：Public 仓库只收公开原文链接和我们的独立概括；不保存公司数据、凭据或未经许可再分发的 PDF。
