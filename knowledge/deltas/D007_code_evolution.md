# D007｜LLM 代码级因子种群进化（P002）

**审批状态（2026-10-21）**：研究者已明确认可**代码级种群进化搜索**作为 CogAlpha 的特色技术机制；本次**未批准任何与此配套的特化缺点**。这不是学术首创性认证。

## 具体机制

- **输入**：经过质量检查和 IC/ICIR/RankIC/RankICIR/MI 等指标筛选的 Python 因子代码，组织为父代候选池。
- **搜索操作**：LLM 在代码层面执行 **Mutation（修改单个因子）**、**Crossover（融合两个因子）**，也可先交叉再变异；新子代重新审查、打分，并使用精英保留进行多代搜索。
- **输出与更新对象**：不断得到新的可运行因子**代码**与种群构成；历史成败案例另外反馈给生成 Prompt。**不是 LLM 模型参数的自训练，也不是严格 RSI**。
- **对照 P001**：P001 的 Writer/Judge/Backtest 主要形成生成—检查—反馈和成功因子知识库；P002 明确增加了**父代选择、精英继承和 LLM 代码级变异/交叉的种群演化控制**，不只是换个说法描述常规反馈循环。
- **作者证据**：[CogAlpha §3.4–3.6](https://arxiv.org/html/2511.18850#S3)、[附录 B.4/B.7](https://arxiv.org/html/2511.18850#A2)。
- **学术新颖性边界**：经典遗传算法早已有变异/交叉；FunSearch、AlphaEvolve 等也有 LLM 辅助的演化式代码搜索。**本次认可的是 CogAlpha 在金融因子挖掘任务上的具体代码种群搜索组织，不是声称首创遗传算子或代码进化**。
- **效果证据边界**：逐步消融中加入演化后 AER 有提升而 IC 可能下降；完整组合表现更好，但单次搜索与累积消融不足以独立证明此模块在任何环境均优越。
- **特化不足**：**暂无用户批准的对应缺点，不强行配对**。此前提出“Python 更灵活所以更难验证”的推断，用户认为牵强，**已否决，不予归档**。
