# D017｜P009：Alpha 候选与内部评价指标的双轨共同演化

**审批：2026-10-22；P009 经研究者明确认可的特色机制①**。属于有辨识度的**项目内机制差异**，并非“LLM 首次写奖励函数”或学术首创结论；论文仍为 arXiv 预印本，研究未独立复现。

## 机制指纹：输入 → 操作 → 更新对象 → 后续输出

- **输入**：当前因子集合、训练段市场评价、内部评分指标库；其中生成因子 `f` 与评价函数 `g` 分由不同角色提出。
- **具体操作**：`alpha-miner` 生成/改进公式；`evaluation-miner` 提出可执行评分函数代码。候选 `g` 经沙盒校验、干运行后以 **trial** 进入版本库；根据多个 `(g(f), training Sharpe(f))` 观测，`n>=3` 且 `|相关|>0.3` 可自动晋级 **accepted**，或走申请/评价小组审查路径；`|相关|<0.05` 触发降级。接受后的新指标可影响后续因子搜索的内部评价依据。
- **真正更新的对象**：**评分函数代码集合 + 技能库的持久版本/晋级状态**（同时因子库继续搜索）。不是把旧评分值重排一下，也不是对生成 LLM 直接做梯度微调。
- **明确不变**：最终外部 holdout 评测器封存；各方法最终 top-30 仍按**训练 IC**选取，不能声称所有最终筛选都由动态评分器接管。
- **作者实际观察**：100 轮中共约 80 次评分指标提案，2 个晋级：`monotonicity_score_v1`（R21，Agent 申请/评审）和 `excess_drawdown_penalty_v1`（R50，自动）；它们都是已有量化实践指标，**不是新度量的学术发明**。8 个技能库中真正出现新增技能晋级的是指标库。

## 严格语义去重结论

- **[D001](D001_nested_feedback.md)/[D003](D003_success_memory.md)**：普通生成—回测反馈及存储有效因子/经验；未把**评价函数本身**作为可编写、验证、注册、迭代的搜索对象。
- **[D010](D010_mcts_multidimensional_search.md)**：P004 按固定多维目标计算分数并将奖励回传到**MCTS 搜索树路径**；D017 直接使**评分函数集合 `g`**发生代码与版本状态改变，不是同一更新对象。
- **[D013](D013_tmb_rl_factor_policy.md)、[D015](D015_hierarchical_evolution_reward.md)、[D016](D016_pool_trajectory_grpo.md)**：奖励结构用于训练**因子生成策略参数**；D017 不以这些特定固定奖励微调 LLM，而是搜索**用于评估因子的指标工件**。
- **[P010](../../papers/P010/README.md)**：用历史 Plan–Reward 训练 **LightGBM 奖励预测代理**，以低成本选择金融语义 Plan；不是 LLM 编写并晋级新评分指标代码。
- **早期同类理念**：Eureka 等已有 LLM 生成奖励程序，不能把“评分函数可由 AI 生成”本身说成首次；本卡只保留**量化因子 / 评分指标双搜索线 + 实际审核晋级**的具体机制差异。

**判定**：与当前 D001–D016 无同义机制卡，且改变了独立的**控制/更新对象**，因此新建 D017 一卡；不按“自动评分”“指标库”“双搜索”“奖励进化”四个别名重复开卡。

## 研究者批准的对应风险（不再另起风险 Delta）

**训练目标共适应 / 晋级依据循环**：新评分指标晋级对照的 outcome 也是 alpha-miner 所追求的**训练 Sharpe**。评估函数可能越来越迎合训练期候选，而不一定改善从历史到未来的判别；**论文作者承认这种循环依赖，但尚未证明其实际造成 holdout 性能失效**。R21 申请晋级的单调性指标与训练 Sharpe 的相关性从约 +0.47 降到 R100 的 +0.158，却因未跌破 0.05 降级门槛仍被接受——说明估计会变化，**不等于过拟合已被实证**。
