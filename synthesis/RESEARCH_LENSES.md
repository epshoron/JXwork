# 当前研究框架：三条互补的问题视角（工作草案）

**日期：2026-10-21**  
**状态：与研究者讨论达成的检索/比较框架，尚非经文献证实的完整分类地图**

## 为什么不用“三大流派”

二手综述归纳出的三类思路有启发，但它们不能被当作互斥的算法家族，也不能当作“辅助生成 → 自动工作流 → 自主进化”那样的能力升级序列。一个系统可能同时采用质量约束、长期反馈学习和多 Agent 协作。

**更稳妥的说法：为了提高 AI 因子挖掘研究的质量，我们可以从三个相互独立的问题出发，研究可组合的工程手段。**

| 视角 | 研究问题 | 典型实现线索（尚待论文证据核对） |
|---|---|---|
| **质量控制（Quality Control）** | 如何提升因子的有效性、创新性、可解释性与稳健性？如何减轻同质化、复杂度和过拟合？ | 金融假设约束、公式/AST 去重、复杂度惩罚、回测与样本外验证、反泄漏检查 |
| **经验学习（Experience Learning）** | 如何把过去的成功与失败转化为以后更好的搜索行动？ | 反馈反思、跨轮次记忆、技能积累、演化与策略更新；必要时模型训练或 RL |
| **推理协作（Reasoning & Collaboration）** | 如何用专业分工、多视角推理、相互批评和裁决提高假设质量？ | Idea/Generation/Evaluation Agent 分工、Debate、投票、评审、专家路由和人机交互 |

## 三者的关系

- **可以并用，不能硬选其一**：一个多 Agent 系统也可具有质量控制与经验记忆。
- **不等于按自主程度递进**：高质量的单 Agent 系统不一定比一个多 Agent 系统“低级”。
- **不直接等于底层算法分类**：GP/RL/LLM、树搜索、种群演化等是实际工程机制，可能出现在多个视角。
- **容易混淆的概念**：多 Agent 不是标准 MoE 神经网络；辩论不是机器学习意义的对抗训练；反馈循环、长期记忆和严格 RSI 或参数更新需要区别。
- **并非穷尽全部问题**：发现、部署、成本、可靠性、评价标准等其他角度可随阅读新增。

## 后续怎样使用，而不是怎样“相信”它

1. 从 LLM/Agent 因子发现的**原始论文**检索少量种子研究。
2. 每篇先写清楚**输入、输出、核心机制、实验与证据**。
3. 再用三个视角做**可多选的问题标签**，有原文证据才打标签；不适用就不填。
4. 比较同一视角下的不同工程实现，以及一篇论文如何结合多个视角。
5. 新论文不匹配时**修正工作框架**，而不是强行归类；最终地图从论文比较中生长。

## 本轮结论的一句话版本

> 先不争论 AI 因子挖掘究竟分成哪几个“流派”。改问：要让系统挖得更好，如何做好**质量控制**、如何实现**经验学习**、如何利用**推理协作**？三者是相互补充的研究问题，可以在同一工程系统中组合。

**注意**：本文仅记录研究讨论达成的工作假设，并非对具体论文效果的验证，正式结论必须附原始来源和实证依据。
