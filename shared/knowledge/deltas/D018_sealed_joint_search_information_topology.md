# D018｜P009：SJS 联合搜索中的分角色信息拓扑与非自我裁定

**审批：2026-10-22；P009 经研究者认可的特色机制②**。明确只讨论**具有角色级访问权限、来源约束及受控指标晋级的联合搜索基础设施**，不把普通多 Agent、保留测试集和有知识库重新包装为新机制。

## 机制指纹：输入 → 操作/控制位置 → 更新对象 → 输出

- **输入**：不同用途的 LLM 角色（因子提案、指标提案、两组独立评价者、研究建议者）、不同 train/test/holdout 数据来源及实验记录。
- **干预位置**：系统在 Agent 之间使用**带类型和接收者身份的非对称投递**；禁止各角色自由读取他人的完整聊天上下文。跨轮只携带**长度/字段受限的评审摘要**；共享 Wiki 的数据按**来源区间 + 消费角色**控制可读字段，因子提案路径看不到指标研究侧的数值化 test 报告；指标侧只能接收限定的四档分类；holdout 全程封存。
- **技能演化控制**：每个版本化技能库只接受本角色写入；内部工件的 **trial/accepted/rejected** 变迁通过系统规则/独立评价，不由提案者单方宣布晋级；轮结束时统一提交状态。
- **更新对象**：权限限定的跨轮消息、带 provenance 的研究记录、版本化技能库状态；实现让 `f` 与 `g` 可以共同搜索而尽量限制无边界的信息流。**没有证明 LLM 底层权重在此系统中自主修改**。
- **边界**：通用最终 OOS 封存只是一项必要条件，不独占地构成 D018；D018 特指**在同一个双轨搜索系统内，用系统强制执行角色、内容、来源、容量、晋级权限的组合控制**。

## 严格语义去重结论

- **[D004](D004_role_separation.md)**：P001 的 Writer/Judge/Reviewer 分工是职责分配和反馈，**没有这一组“接收方字段过滤 + 来源标记 + 跨轮容量约束 + 独占写权限 + 系统晋级”的联合搜索控制协议**。区别发生在**信息路由与工件权限**，不是角色个数。
- **[D005](D005_oos_evaluation.md)**：时间切分和知识库冻结属通用验证原则；**不以普通留出集再次建卡**。本机制额外在每个角色的每次 Wiki 读取和摘要投递时强制数据权限。
- **[D003](D003_success_memory.md)**：P001 复用已成功的 Alpha 案例；P009 的技能库包括**评分器代码和可接受状态**，且按角色所有权限制更新；这里只保留**封闭的信息拓扑**，指标代码演化另见 D017。
- **[D001](D001_nested_feedback.md)** 与 **[D010](D010_mcts_multidimensional_search.md)**：反馈循环和树节点调度都不是“跨角色、按数据来源限制的信息边”；两种机制操作对象不同。
- **[D017](D017_joint_alpha_metric_evolution.md)**：D017 讲**搜索什么（f 和 g）及 g 如何晋级**；D018 讲**谁能看到什么、能写什么、反馈何时以何种信息粒度进入下一轮**。为避免交叉重复，仅记录拓扑的联合权限控制一次。

**判定**：与 D004/D005 有背景联系，但 P009 实质增加可核查的**系统强制信息传输与权限干预位置**。作为项目内独立技术单元保留 D018，不声称是「首次多 Agent」或「首次保密测试集」。

## 研究者批准的对应实证缺口（不新建风险 Delta）

**必要性未独立验证**：作者在 §6 / Appendix A.9 承认**没有**「单 Agent 同时搜索因子/指标、其余可进化能力不变」的对照，因此 F1 角色隔离的独立贡献还未被实验证实。完整 Agora 100 轮且带 PPO 中继，冻结技能库 B6 主要为 5 轮并同时关 PPO（另有 20 轮预加载指标对照），**轮数与中继/库演化混杂**，不能把整个 Sharpe 差距直接归因于这一拓扑。这是**P009 特定实验归因不足**，不是“隔离肯定无效”。
