# T001｜研究者已确认的特化不足及待检验问题（2026-10-22）

> 每条**对应一个已审批特色机制**，保留作者证据与独立推论的边界；不列泛泛“Prompt 会过拟合”“测试有噪声”等通用套话。

## 1. TD001 ↔ 文本层自指优化尚未扩展到算法/工作流结构

- **对应特色设计**：[TD001｜P 与 M 绑定的自指进化](../../knowledge/deltas/TD001_coupled_task_mutator_prompt_evolution.md)：LLM 可以修改任务指令 P，也可以改指导修改 P 的变异指令 M。
- **特化边界**：外层锦标赛、五类变异操作与 Prompt 调用拓扑及外部 Fitness 定义仍是设计时固定的。改进 M 不代表系统学会自动重新设计整个搜索算法、工具路由或 Agent 执行图。
- **证据身份**：原文 §6 直接说明当前只进化 Prompt 内容，提出未来可能考虑更复杂的条件 Prompt 策略。**这是作者承认的研究范围，不能当作已经发生的性能故障。**
- **如何验证扩展价值**：在可比较的任务/模型/预算下，区分“仅优化 P/M”与“允许优化调用结构/工具流”的收益及稳定性；这只是后续研究测试问题，**未批准为系统方案**。

## 2. TD002 ↔ Few-shot 正确示例可能掩盖任务 Prompt 自身的作用

- **对应特色设计**：[TD002｜成功解答反推 Prompt + Few-shot 上下文演化](../../knowledge/deltas/TD002_success_trace_prompt_induction_context_evolution.md)：Lamarckian mutation 以正确工作过程反推新任务指令，context shuffling 则改变优秀样例集合。
- **具体观察**：作者在 Appendix J.5 报告，few-shot 场景中示例有时支配评分，部分任务 Prompt 漂移成 `The mutant`、`mutant` 等无意义文本，却仍依赖示例起作用。
- **对应的判断边界**：**任务组合表现好 ≠ 任务 Prompt 单独变好**；不能从这段观察推断模型权重学习了能力、全部基准泛化无效或示例机制毫无价值。
- **怎样进一步验证**：冻结示例比较不同 P；冻结 P 比较不同示例；将生成的 P 脱离 Few-shot 上下文测试，再检验独立任务泛化与提示稳定性。这是基于作者案例的**待检验方案**，尚无我们自己的实验结果。
