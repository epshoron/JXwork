# TD011｜T004 ADAS：历史 Agent 设计档案作为下一轮结构搜索踏脚石

**审批**：2026-10-22 研究者批准 T004 特色②与对应特化问题②。项目内具体机制，不声称“使用记忆”“积累经验”本身为全球首创；未独立复现。

## 机制指纹（输入 → 干预 → 更新对象 → 输出）

- **输入**：历轮生成的**Agent 设计思想、可执行程序代码及真实任务评测成绩**；发现档案既可能从预置人类设计种子启动，也可以从空档案启动。
- **具体干预**：上层 Meta Agent 在每轮设计新 `forward(taskInfo)` 前阅读历史档案，将既有结构/组件和失败或一般表现的设计视为 **stepping stones（后续探索可借用的中间构件）**，据此提出、实现并评估另一设计；新设计及分数再写回档案。
- **更新对象**：**跨轮可供设计者读取的结构化设计经验与新 Agent 候选集合**，不是基础模型参数，也不是成功答案的简单示例记忆；评测指标/外层算法没有随档案而自动学习成新权重。
- **原文证据**：§3、Figure 3 的 ARC 探索谱系展示部分早期未必最佳的结构后来能提供设计思路；Appendix J / Table 6 对比人工种子与无种子初始化的影响。

## 严格语义去重

- **T001/TD002**：从**正确工作过程**反推新自然语言任务 Prompt 并更新 few-shot，作用对象不是**Agent 程序/模块结构 + 评价结果**。
- **T002/TD004–TD005**：已存在 Prompt 候选通过 Pareto 父代选择或谱系式局部合并；ADAS 本卡强调 Meta Agent **读取累积的整套 Agent 设计与代码**，直接为**下一轮新代码生成**提供构造材料，而不只是固定拓扑下的候选选择。
- **A/D003（P001）**：保存并检索已成功的量化因子；ADAS 保存的是**Agent 设计/代码/成绩及中间设计**，不只是成功实例，也不服务于同类因子检索。
- **A/D020（P010）**：LightGBM 学习语义计划→奖励预测并调度候选；ADAS 不训练这种代理奖励模型，仅把真实已试 Agent 的设计与成绩提供给设计 LLM。
- **本卡不重复 [TD010](TD010_executable_agent_program_search.md) 的代码搜索空间**；它唯一刻画的是**历史代码设计/实测反馈如何改变下一轮生成上下文**。

## 对应获批特化不足②：初始种子偏置及持续档案的独立贡献尚不充分隔离

- **原文直接观察**：Appendix J / Table 6 中 MGSM 的有人工设计种子 **53.4**，空档案起步 **67.5**；其余研究域总体上有种子更好。结果表明**预置人工种子的益处并非单调一致**。
- **证据边界**：空档案初始化**不等于**搜索期间完全禁用 Archive；两组仍可继续写入后续 Agent 设计。因此该消融**不能单独证明持续 Archive 有害或有益**。作者对无种子条件更自由探索的解释尚非独立的因果证明。
- **待验证问题**：存储哪些设计（最佳、失败、多样化中间方案）、如何选取/压缩历史上下文、在何种任务下历史先验限制新方案探索？固定任务、模型、上下文与搜索预算，正交比较「有/无预置种子」和「有/无迭代读取 Archive」，观察设计多样性、增量结果与独立测试表现。
