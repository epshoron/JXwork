# TD010｜T004 ADAS：以可执行 Agent 程序为对象的开放式结构搜索

**审批**：2026-10-22 研究者批准 T004 特色①与对应特化问题①。这是项目知识库中的机制辨识度，**不宣称代码生成或 Agent 设计搜索的学术首创性**；无独立复现。

## 机制指纹（输入 → 干预 → 更新对象 → 输出）

- **输入**：事先规定的任务、可调用的基础模型与工具接口、当前 Agent 代码/设计档案、任务评价指标和搜索预算。
- **具体干预**：上层 Meta Agent 先提出设计思路，再编写可执行的 `forward(taskInfo)` Python 逻辑；可在框架允许的范围内调整角色/模块、Prompt、调用先后、并行分支、反馈循环与聚合方式。候选经过模型自检、必要时报错修复（至多五次）、真实任务评价后进入设计档案。
- **更新对象**：**下层 Agent 的可执行程序及调用拓扑**，而非仅任务 Prompt、基础模型权重、上层 Meta Agent 权重或预设评价函数。输出为多个经实际测试的候选 Agent 实现及得分。
- **原文范围**：论文 §2–3、Figure 1–3、Appendix C/D/I；Figure 3 的候选展示并不意味着无限的 Agent/工具权限已实现。

## 已有机制语义去重

- **T001/TD001–TD002**：搜索任务/变异 Prompt、Few-shot 上下文，不直接把下层的整个模型调用程序作为搜索对象。
- **T002/TD003–TD005**：反思和替换模块 Prompt、按样例 Pareto 选父代或合并已有模块 Prompt，底层控制流固定；T004 允许重写 `forward` 组织结构。
- **T003/TD008–TD009、T005/TD006–TD007**：重点是从 Agent 轨迹或自评偏好生成模型训练单元并更新模型权重；本机制不进行 SFT/DPO/RL 权重训练。
- **方向 A D007（P002）**：搜索和变异的是**金融因子计算代码**，而非执行/协调基础模型的 Agent 程序；**方向 A D017（P009）**编写的是可执行**评价指标代码**，更新对象仍不同。
- 与 [TD011](TD011_agent_design_archive_stepping_stones.md) 的职责边界：**本卡定义可被生成与搜索的工件**；TD011 则是历史工件如何作为后续设计上下文回流。普通程序运行/报错修复不单独再建卡。

## 对应获批特化不足①：性能导向未隔离 Agent 结构与额外计算预算

论文主评价以 F1/准确率等**任务表现**为主；生成式结构搜索允许任意增加若干模型调用、评审和反馈循环（受现有接口/预算约束）。因此，评分改善**可能同时来自设计质量与更高推理调用/Token 消耗**，仅凭准确率不能判断性价比或延迟表现。原文 §6 明确将多目标、成本/时间/安全评价列为后续研究；Appendix K 报告论文当时的 API 开支，但非现代市场定价。

**证据身份**：作者承认多目标优化尚未纳入主实验；“额外计算解释多少性能提升”是**待核归因问题**，不是已证明只靠堆计算。

**核验**：保持底层模型、任务与算力/调用/Token 预算相同，控制最大 LLM 轮次和延迟，在 Pareto（准确率、费用、延迟）层面对比固定设计与代码搜索，测量不同结构的净增益及复现性。不把一般“模型成本高”单独包装成创新风险。
