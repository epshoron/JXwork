## 特色机制①｜共同搜索因子与内部评分指标（D017）

**输入 → 具体操作 → 更新对象 → 输出**

- **输入**：历史数据、现有 Alpha 候选与可用内部评分指标。
- **操作**：`alpha-miner` 搜索因子表达式 **f**；独立的 `evaluation-miner` 提出可执行新评价函数 **g**。指标经 AST/沙盒/干运行校验先入 trial；当累计至少 3 组「指标得分、**训练段 Sharpe**」观测且绝对相关 `>0.3` 时可自动晋级，或经 Agent 申请、评价组审核晋级。已接受指标进入版本化技能库、影响后续轮次可用评价依据；相关 `<0.05` 时可降级。
- **更新对象**：**评分函数集合与其 trial/accepted 状态**，同时因子生成线继续按反馈改进候选。**最终封存评测程序不随之变动**；论文统一的最终 top-30 仍按训练 IC 筛选，不能说已完全用进化指标取代最终组合构建规则。
- **观察到的范围**：作者报告 100 轮提出约 80 个候选指标，实际只有 `monotonicity_score_v1`（R21，申请/评审）与 `excess_drawdown_penalty_v1`（R50，自动）两项晋级；两者属于常见量化指标，并非作者发明的金融度量。8 类技能库中，实质演化只观察于 **metric** 库。

**与旧机制的严格去重**： [D010/P004](../../knowledge/deltas/D010_mcts_multidimensional_search.md) 虽同样多维评价，但改变的是 **MCTS 搜索路径与节点反馈**，没有把 `g` 当可生成、检验、晋级的代码工件；[D013/P007](../../knowledge/deltas/D013_tmb_rl_factor_policy.md)、[D016/P005](../../knowledge/deltas/D016_pool_trajectory_grpo.md)、[D015/P008](../../knowledge/deltas/D015_hierarchical_evolution_reward.md) 是利用**指定奖励更新生成策略参数**，不是更新奖励/评分函数**集合**；[P010](../P010/README.md) 从 `(Plan,reward)` 学习 LightGBM **奖励预测代理**，目标是选择语义计划，不是由 Agent 编写新评分公式并进行指标晋级。一般 LLM 编写奖励程序有 Eureka 等前作，本项不声称学术首次。

**对应不足①**：共同演化需要内部晋级依据，而 P009 的晋级反馈与因子追求的训练 Sharpe 同源，可能导致评分器和候选因子共同迎合既有训练目标；作者也明确承认这种循环性。详见 [IDEAS.md](IDEAS.md#不足①评价指标晋级依据的自我强化)。

## 特色机制②｜SJS 角色权限与有边界的信息流（D018）

**输入 → 具体操作 → 更新对象 → 输出**

- **输入**：因子/评分器两条搜索线、两个分别含三实例的评价面板、按数据区间标记的实验记录。
- **操作**：SJS 规定五项拓扑约束：**(F1)** 生成与裁决分角色；**(F2)** 跨轮只送容量受控的摘要；**(F3)** 按角色及 train/test/holdout 来源过滤读取权限；**(F4)** 可执行、版本化且独立拥有写权限的技能库；**(F5)** 由系统/评价者而非提议者决定试用/晋级/降级。跨角色采用不同内容投递、独立上下文和受控 Wiki；验证区间的指标侧反馈最多暴露**四档类别**，不向因子提案路径公开对应数值；**2026 的最终 holdout 全程封存**。
- **更新对象**：跨轮有限摘要、权限化记忆与各技能库注册状态；不是「所有 Agent 共享全部聊天历史」，也不是已经证明基础 LLM 权重自我进化。
- **输出**：允许新因子和新指标在指定信息边界内交替探索，而最终外部评价器与封存段保持独立。

**与旧机制的严格去重**：[D004/P001](../../knowledge/deltas/D004_role_separation.md) 仅是 Writer/Judge/回测分工；本机制的额外**控制点**是**按接收方投递内容、按数据来源限制可读字段、跨轮限幅、独立所有权技能库、非自我裁定的晋级**这一组可核查的系统约束。[D005/P001](../../knowledge/deltas/D005_oos_evaluation.md) 的时间切分与最终冻结是通用评测原则，**不单列为 P009 创新**；D018 只保留它如何以角色/字段/来源为粒度实装到联合搜索的系统拓扑。**不宣称首次多 Agent、首次 OOS 或首次角色隔离。**

**对应不足②**：尚无「**单 Agent 同时生成 f/g、但仍可进化技能库**」的直接对照，无法归因 F1 的必要性；冻结库对照主要仅 5 轮且 PPO 也关闭（Agora 100 轮），与共同演化/信息隔离效果无法完全拆分。详见 [IDEAS.md](IDEAS.md#不足②关键对照不充分机制贡献尚不能独立归因)。

## 证据、结论与审批边界

- **原文依据**：[§3.2–3.7 SJS 的 F1–F5](https://arxiv.org/html/2606.29194)；[§4.3 指标晋级及角色通道](https://arxiv.org/html/2606.29194)；[§5.7–5.8 技能库演化与消融](https://arxiv.org/html/2606.29194)；[§6 Limitations / Appendix A.9](https://arxiv.org/html/2606.29194)。
- **报告不是独立证实**：完整 Agora 单种子，封存区间只有 2026-01 至 2026-05 的 91 个交易日，报告多空 Sharpe +1.87 且表现偏空头侧；作者报告的并列基线和消融尚不足以确认两项机制各自的因果增益或普适性。
- **去重审查**：对照 D001、D003–D005、D007、D010、D013–D016 及 P010；创新①的新控制对象是**评分函数代码/晋级状态**；创新②的新干预点是**角色级信息路由/来源过滤/系统晋级权限**。各保留一项，**不另建**“双 Agent”“知识积累”“验证集隔离”“新奖励函数”等同义机制。**两项不足仅放本篇 IDEAS，不额外拆出通用风险 Delta**。
