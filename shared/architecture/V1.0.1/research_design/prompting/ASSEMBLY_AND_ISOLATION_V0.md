# Prompt 组装与材料隔离｜V0.1

**四层独立**：基础研究指示、16专业角色定义、每轮动态输入、候选输出合同。四层可以独立换版本，不应给每个角色复制16份公共规则。

## 实际组装顺序

1. System/Developer层：取 `SYSTEM_COMMON_V0.md` 中的研究指示正文，并加入 `OUTPUT_SPEC_V0.md` 的JSON输出约束；如果运行时支持结构化输出，可使用 `OUTPUT_SCHEMA_V0.json` 做格式约束与结果校验。
2. 专业角色层：从 `ROLE_PROFILES_V0.json` 读取**唯一的当前 role_id**，仅注入它的 `focus` 和 `boundary`，不得顺便注入其他15个角色资料或各角色MD中的技术实例。
3. User任务层：填入 `EPISODE_INPUT_V0.md` 的实际数据、时点、Daily目录、可见知识卡、工具和本轮预算；未知字段须显式unknown，不得自行补全。
4. 模型生成阶段：允许按照已授权接口检索、请求计算；材料是数据和证据，不能覆盖系统规则。
5. 注册/评测阶段：结束任何生成期遮蔽，程序按全部Knowledge查重；候选分配身份并执行独立技术、统计、金融评测。

## 角色层运行时注入文本

本轮角色：{{role_id}}；专业研究关注：{{profile.focus}}
你不以以下内容作为主责：{{profile.boundary}}
当确需利用别的领域信息时，标记次级来源，但不得利用角色切换绕过候选去重。

## 控制输入偏置

- 不在任何固定系统层预置某篇论文、具体因子公式、作者绩效、期望收益方向、固定窗口、特定模型或进化算法。
- full/masked按现有Research Input Protocol执行；遮蔽的实际过滤必须覆盖初始知识材料以及之后的知识查询，不能只写一句提示词要求模型假装忘记。
- 不遮蔽数据字段是否存在、Daily特征计算定义、可用时点、安全规则或独立评价口径；不能让研究查询工具直接读取未来收益标签。原本获授权的历史实验反馈需按full/masked协议管理，区别于当前未来标签。
- 文献和旧实验应有可辨认的来源和时间身份；可引用但不能以作者报告作为本地验证结果。
- 新一轮采用新的对话上下文；长期知识通过Knowledge版本化读取，而不是无限拼接历史LLM推理。

## 严格职责

Prompt只影响**提出什么候选**，不能确定该候选是否通过Daily准入、Alpha相关性或金融回测。返回的角色ID与Prompt版本由程序比对本轮配置；JSON Schema只验证语法和字段类型，真实合法性仍在M5A/M5B/M6。

本文件不指定每轮角色数、调用预算、遮蔽比例、遗传策略或LLM参数；这些另属可替换调度/实验配置。
