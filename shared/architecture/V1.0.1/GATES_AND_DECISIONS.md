# V1.0.1｜Daily / Alpha 门槛与失败判定

> **确定项（研究者 2026-10-29 拍板）**：Alpha 采用“技术/统计 → 金融”两关，Knowledge 留全量；`Ret > 3%` 与 `SR > 1` 同时满足即正式成功；Daily 入库相关性严格 `<0.6`；Alpha 对成功胜者的最大绝对相关性严格 `<0.65`；Score **不参与任何硬门槛**。本文没有假装未知的统计实现已被验证。

## 0. 一开始就记入 Knowledge

每个新候选先产生 Factor 和 Experiment。即使无法运行或有未来泄漏，仍保留候选代码版本、原因、来源和失败状态。区分：**实验记录入 Knowledge** / **通过检查进入金融回测** / **正式成功标签**。三者并非同一个“入库”。

## 1. 第一关：Alpha 技术/统计（昂贵金融回测之前）

**至少涵盖**：真实数据字段与依赖、时间合法性与独立未来信息检查、实际可执行与复现、CSV 键/粒度/覆盖/NaN/Inf/常数及异常值、严格重复与有意义的相关性/冗余检查。基础相关性检查只用可见因子值，不先跑完整投资组合回测。具体顺序可在程序内先做低成本检测，降低浪费。

结果：
- `pass`：质量/合法性以及已冻结的统计条件全部通过；才允许进入第二关。
- `fail`：已证实非法、不完整、不可执行、退化或违反已冻结的相关规则（包括 Alpha `max_abs_corr>=0.65`）；保存原因与数值，金融字段 `NULL`。
- `blocked`：缺字段、权限、版本、统计规则未定、样本不足或程序异常；不能当作有效回测的收益失败，金融字段 `NULL`。

**已确认的 Alpha 相关性规则**：比较集合仅含 Knowledge 中 `qualified=true` 且 `internal_executed` 的已成功 Alpha，不含失败者和作者外部报告。用因子值计算对每个成功胜者的相关性，取 `max_abs_corr = max(abs(Corr(new, winner)))`；严格 `<0.65` 通过，`>=0.65` 记 `statistical_fail/redundant`，金融评价不执行，不能宣称该因子不盈利。若没有任何成功胜者，则相关性子检查记 `NO_REFERENCE` 并视为通过，**仅此一项被免除**。之后随着成功者增加，参照集合增加。应保存胜者 ID/集合快照、最大相关值、最相似胜者和检查版本。

**仍未冻结**：Pearson/Spearman、日期与股票对齐、日截面平均还是全量拼接、最小重叠样本、跨数据版本可比性。实现尚未冻结的统计方法时不能假报 PASS。Daily `<0.6` 属于独立规则，不能套用 Alpha 的 0.65。

## 2. 第二关：Alpha 金融评价

对第一关 `pass` 的候选执行 [Evaluator V1](../../evaluation/PORTFOLIO_SCORING_STANDARD.md)，并存储 `ret, sr, dd, to, cost_ann` 及必要的日级明细。评测一旦有效完成，不管表现高低都要保存这些金融数值。

**正式成功的唯一门槛**：

[
\boxed{\mathrm{qualified}=\left(\mathrm{Ret}>0.03\right)\land\left(\mathrm{SR}>1\right)}
]

这里的严格不等号表示等于 3% 或等于 1 **不合格**。当 `ret`/`sr` 不可计算，状态是 `evaluation_error/blocked`，不是将其当 0。实验状态：
- `qualified`：两关通过且两个金融硬条件全部满足；**正式存档，无额外 Selected/Alpha 库**。
- `financial_fail`：第一关通过、第二关有效完成，但 `Ret <= 0.03` 或 `SR <=1`。
- `technical_fail` / `blocked` / `evaluation_error`：不是金融上已测失败，保留明确故障层级。

**收益口径**：已有 Evaluator V1 使用算术年化**毛**收益与毛 Sharpe。将 `Ret >3%` 连接到 `ret_ann_gross` 是本版本与既定 Evaluator 的一致性工作口径；公司真实回测若另有净收益定义，必须另行确认，不能暗中改旧指标含义。样本外时段与股票池边界同样按实际研究数据在实施前确定。

## 3. Daily 库的独立准入

Daily 沉淀 Agent 只负责中间特征，不能以母 Alpha 的盈利成功代替技术准入。**每个新 Alpha Factor 必须由独立 M1 回看一次，最多提名一个可沉淀候选（允许 0 个）**；已有 Daily 视为完整构件，不向下拆解，允许在其基础上生成新的 A2。候选新增必须满足**独立性/中立性、明确经济含义、非平凡性、非重复性**四项原则；不以基础数据相关性、算子数量、代码复杂度或缓存成本代替非平凡性判断。完整说明见 [Daily Curator 已确认规则](DAILY_CURATOR_RULES.md)。历史候选 G1–G4（实际数据、时点、可复现、去重）可作程序检查项；**旧 v0 草案的 `S/U/B` 打分阈值不作为本版准入规则**。

**新确定的必过硬条件：与已有 Daily 因子/特征的相关性严格小于 0.6。** 计算必须记录比较对象、时间/股票交集、缺失处理、统计方法及计算版本。若尚未约定 Pearson 还是 Spearman、是否取绝对值、跨日期聚合/时间窗口以及空库处理：**不得宣称该检查已经通过**；需先冻结定义，才允许自动批准。相同定义应复用现有 ID，不以更名绕过。

## 4. Score 是可选的事后排序计算

[
\mathrm{Score}_{V1}
=1.0\,R_{\mathrm{ann,gross}}
+0.05\,SR_{\mathrm{gross}}
-0.1\,MDD_{\mathrm{gross}}
-C_{\mathrm{ann}}.
]

原始评价数学保持不变；`C_ann = 252 * 0.001 * mean(TO_daily)`。不需要在写入 Knowledge 时计算或持久化 Score，**需要按分数排序时可用 Python 重算**。只改线性系数不需重跑回测；更改数据口径或市场假设则必须重新评估。

## 5. 先处理什么，后处理什么

实际推荐顺序：注册 → 廉价字段/运行检查 → 未来信息安全硬关 → 基础统计/重复/相关 → **第一关最终 PASS** → 金融 Evaluator → 保存金融原始指标 → `qualified` 标签。部分顺序属于性能优化建议；无论内部怎么重排，**安全/统计未过不得触发金融成功判定**。
