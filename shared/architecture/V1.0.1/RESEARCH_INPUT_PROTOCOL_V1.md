# V1.0.1｜Research Agent 输入与偏置控制协议

> **2026-10-29 已纳入现行 V1.0.1 架构。** 确认流程边界，具体遮蔽参数和真实有效性仍须验证；当前尚未实现。

## 1. 已固定的边界

- **只有四个逻辑库**：Min（分钟原始数据、字段）、论文/研报（人工收录的外源）、Daily（持续更新的日频中间特征）、知识库（**文献候选/作者报告** + **内部真实 Alpha 成败实验**）。前二者不接受实验结果自动回写；后二者进入研究反馈循环。
- **独立 Daily 沉淀 Agent**：首次及新文献入库时，形成/核验 Daily 中间特征，**并把文献假设、作者结论、计算依赖及证据状态写入同一个知识库**。研究后发现新的可复用中间表达式也由它审查。原文不删除，供复核和按章节追问。
- **研究 Agent 数量与角色未定**：用可配置的 N 表示，不等于照搬 P002 的 21 个角色。
- **统一程序读取接口**：四库各自保留真实结构，Agent 只接触统一结构化记录和工具。这个接口**不是第五库、也不是新增检索/材料分配 LLM Agent**。第一版不开发复杂动态材料调度器。
- **正确性底线不得随机遮蔽**：真实 Min 字段、Daily 计算定义与依赖/信息可用时点、代码执行约束、数据许可边界、Evaluator 规则始终可见。CSV 交给 Python 读取分析；论文全文默认不进入 Prompt，按章节查阅。

## 2. 每次研究运行（episode）的明确步骤

### 0. 初始化
程序固定本次 `run_id`、数据/知识/目录版本、研究任务、模型配置、随机种子 `seed`、信息曝光模式与资源预算。每次尝试建立**独立的新对话上下文**，不继承上一轮冗长的失败推理；跨轮经验通过知识库读取。

### 1. 提供足够的真实研究材料
始终提供 Min 字段可用性、全部或可分页的 Daily **特征定义目录**（不是 CSV 全数值）、知识库的**结构化金融现象/候选/实验卡片**与论文来源索引。冷启动时内部实验为零，知识库仍可包含文献原始假设和作者报告，标为 `external_reported / unverified_internally`。

初期精炼记录量小且在预算内时，可将可见知识卡与 Daily 目录**一次完整提供给 Agent 自己阅读**，不要求先通过某个系统挑出 Top-K。预算不够则程序分页提供、Agent 自己查和展开，不自动假装全量已读。

### 2. 输入信息曝光模式（可开关；初版不固定比例）
- `full`：展示全部当前可读的结构化研究卡（仍不等于全文论文/原始数据）。用于正常复现、利用知识和建立基线。
- `masked`：在**开始生成前**，程序按 `seed` 对**整组研究结论/Alpha 谱系**做可复现的随机遮蔽，隐藏被遮蔽组中现成的候选公式、作者声称的有效性和内部成败记录。它不是随机删 Min 字段、Daily 特征定义、时间安全限制或原始数据。遮蔽作用于生成阶段的卡片呈现和通常的知识查询；不能只是 Prompt 里说“假装没看到”。Agent 仍有真实的数据分析和金融现象材料用于推理。
- 模式与遮蔽强度是**实验配置**；V1 不把两种模式的调用比例、遮蔽概率或是否优于 full 当成已验证事实。初次试运行可各跑一组同预算候选再比较，避免先调一堆超参数。
- `masked` 不会抹去 LLM 预训练知识，也不保证其它 Daily 定义完全不暗示某个观点。因此它是**降低显式输入固着的实验手段**，不是证明“无偏”。
- 若研究者或 Agent 需要查原始论文来核验事实，可记录该主动查看/解除遮蔽的行为；不能将安全、事实核验与随机遮蔽混同。

### 3. Agent 自己探索、生成
Agent 自主阅读被允许的材料、请求 `read_material(id)`、`read_source_section(id, section)`、`analyze_daily(feature_ids, question)`、`request_daily_feature(...)`，并提交包含**金融假设、公式/代码、依赖字段、时点、实际参考来源**的候选。禁止凭空补造论文证据、字段、运行结果或来源引用。按需数据分析由程序返回可检查统计，不把全量 CSV 文本贴到 Prompt。

### 4. 候选产生后：全库审查 → 独立泄漏关卡 → 独立评价
一旦有具体候选，关闭本次生成期的遮蔽；程序可访问**整个**知识库/Daily 特征目录，检查表达式等价、依赖和历史相似失败。之后将该候选送入**独立的未来信息 / 数据泄漏检查模块（硬关卡）**，检查信号、底层数据、计算依赖的可见时点。**未通过或无法确认的候选不得进入评价模块**，只记录阻断原因并返回修正。只有通过后才进入**独立的统一 Evaluator**（已有 V1 评价口径不变）。遗传变异生成的候选也必须走相同关卡，不许直接送 Evaluator。历史失败**不是自动否决新候选**，因为数据版本、市场或时间窗口可能不同。程序实际检查优先，LLM 不能自判“通过”。本阶段只确认模块接口，不展开检测规则与评价模块内部。

### 5. 双回流与记录
- **知识库**：追加每一个实际候选及对应实验（含代码失败、不可计算、回测差、有效等），连同 `run_id/seed/mode/exposed_card_ids/hidden_group_ids/query_log/model_version/data_snapshot/score_version/parent_refs`；作者文献结论与内部实验身份分开，不因回测失败修改原文事实。
- **Daily 库**：新发现可复用中间表达式仅提出申请，由**独立 Daily 沉淀 Agent**核验后决定是否物化。母 Alpha 是否成功不直接决定准入。
- **遗传进化**：利用知识库的候选和真实评价选择父代、变异/交叉后再回统一检验；具体使用 LLM 还是程序尚未定。遗传种群不是新的数据库，也不是正式因子池。

## 3. 第一版最低验证标准与故障归属

首先跑得起来，再比较 `full` 与 `masked`：相同的数据、模型、运行预算及评估口径；观察**可执行率、严格重复、底层 Daily 特征覆盖、谱系集中程度、真实信号相关性、样本外 Score、成本**。多样性不直接加进既定 Score V1，也不能把“公式不同”误写为“金融机制不同”。

**失败怎么处理**：
- 数据缺字段、代码错误、未来泄漏、时间错位、重复入库 → **Research Loop 内的工具/流程工程 Debug**，不等 Meta Loop。
- 长期固着、不同输入条件探索差、Agent 提示词/查询行为/探索策略需要改进 → 将可重复的跨轮结果交给未来 **Meta Loop 做受控比较和配置改进**，不是 Meta 一定能优化成功。
- V1 不需要事先确定最优 Agent 数量、遮蔽比例、检索算法、提示词参数和遗传调度。未跑通的实验结果不能称为系统验证成果。
