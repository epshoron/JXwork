# V1.0.1｜M1 Daily 沉淀 Agent：已确认设计规则（2026-10-29）

> 本文只固定研究者已讨论确认的**沉淀职责和准入原则**，不是 Agent Prompt、JSON Schema、接口或已部署实现。待 Min、论文/研报、Daily、Knowledge 四个逻辑库接入并核实后，再共同设计完整 Prompt、调用格式、数据结构与工具链。历史 [Daily Admission V0 草案](../../../assistant/handoffs/DAILY_ADMISSION_AGENT_V0.md) 的 S/U/B 评分及物化分层阈值**不采纳为现行准入标准**。

## 新增：Base 与 Curated 的边界

Daily Feature 同时包含 `base`（分钟 Close 经受控程序生成的基础日频字段）和 `curated`（本文件 M1 审核发布的研究中间特征）；所有 M1 审核尝试进入独立 Review，失败/阻断/无候选也记录。Base 不适用 M1 的非平凡性准入，不参加 Curated 相关性参照，但必须真实、合法、可复现。详见 [四库实施契约](FOUR_LIBRARY_RUNTIME_CONTRACT.md)。

## 一、沉淀什么、由谁负责

- **M1 独立 Daily Curator** 负责从 Min、文献/研报和研究过程发现、判断、验证并沉淀可复用的日频中间特征；**M3 的 16 个 Research Agent 只负责提出日频 Alpha 候选**，不替 M1 提取或审核 Daily。
- **每当产生一个新的 Alpha Factor 候选，M1 必须独立回看一次**，不以该 Factor 最终是否盈利、是否通过金融回测决定是否回看。M1 的文献/原始数据主动研究入口继续保留，不因本规则取消。
- 回看一个 Alpha Factor 时，**最多提名一个**有价值的中间特征；可以是 **0 个**。不为了凑名额强制提取，不穷举公式子式、不做递归拆解、不以提取数量为目标。发现多个可能的结构，也只选择其中一个最值得保留的完整结构进入验证。
- **已有 Daily 特征作为完整构件复用，不再向下拆解。** 新 Factor 可以以已有 A1 为基础，与其他信息结合或做有意义的新变换，从而形成新的候选 A2；A2 不因继承 A1 自动合格，也不要求只能由一种基础信息构成。
- 这里的沉淀不是固定算子树分解，更不是把 `Rank`、简单均值、临时变量等每一层都存入 Daily；Research Agent 仍可自由以 Python 表达金融假设。

## 二、四项准入原则：全部满足才能新增 Daily

1. **独立性 / 中立性**：脱离原 Alpha 的最终预测目标和组合后，该结构仍是定义完整、可独立计算的日频指标。
2. **明确经济含义**：能用一句具体、准确的话讲清楚它**实际度量了什么市场现象或经济关系**；不得凭计算式臆断主力意图、因果关系或盈利预测能力。
3. **非平凡性**：相对原始数据和已有 Daily 基础，形成了**有实质内容的新测度或关系结构**，不能仅仅是五日均值、普通波动率、简单反转/标准化或几层常规算子的机械叠加。**不设算子数、代码行数、嵌套层数硬阈值；复杂不等于堆叠，简单公式也可能表达独立经济关系。**
4. **非重复性**：不得与已有 Daily 定义等价；实际特征值与**已正式发布的 Curated 特征**的相关性必须严格 **< 0.6**（等于 0.6 不通过）。仍须遵守已有技术准入：真实字段、合法信息时点、正确且可复现的日频计算。相关系数种类、绝对值与否、样本对齐、空库行为等**尚未冻结**，不能在未实际验证时宣称通过。

**不新增“与原始行情字段相关性低”或“达到指定复杂度”作为硬门槛。** 与原始量价数据相关性低，并不能证明有新经济含义或非平凡性；对已发布 Curated 的 `<0.6` 是已有独立去重硬条件（不包括 Base/审核失败记录；定义完全等价仍不得重复），而不是复杂度分数。

## 三、选择与沉淀的结果

- **每个 Alpha Factor 回看：最多一个候选；最终新增 Daily 为 0 或 1。** 未通过任一项则不新增，不为了一个 Factor 多次改选次优子结构来凑入库数量。
- 若完全等价于已有 Daily，**复用已有特征 ID，不创建新条目**；新特征通过全部检查才可入库。
- 通过后提供**清楚的语义名称、稳定唯一编号**（如 `DLY_0001｜日内量价方向一致性`），并保留精确计算定义、来源及时间依赖，方便其他 Research Agent 看懂和复用；示例名称不代表真实特征已通过。
- 对“是否新增 Daily”的业务判断保持简单：**是 / 否**。遇到工具缺失、证据不足、尚未冻结的相关性口径等，只能**不批准新增并说明验证缺口**，不能冒充已验证不合格，更不能假报通过；工程记录及具体格式待后续联合设计。
- **Daily 准入不以母 Alpha 的 Ret、Sharpe 或 Score 为条件**。是否缓存、如何物化、每日更新和正式接口格式，均待四库接入后再设计；不恢复此前 S/U/B 计算经济性打分作准入条件。

## 四、边界与后续工作

这版规则是**业务原则已确认、执行方式尚未定稿**：不在此写 Agent System Prompt、few-shot 案例库、输出 JSON、API/CSV Schema 或程序实现；也不声称已通过真实数据测试。四库实际字段、目录和数据读写方式确认后，再结合真实复杂 Factor 示例一起敲定 Prompt 与格式。
