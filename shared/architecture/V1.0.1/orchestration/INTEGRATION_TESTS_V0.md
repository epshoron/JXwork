# Research调度 + Masking + 总编排｜合成数据验收

这是**交给公司开发Agent的测试设计**，不代表任何测试已经运行。采用合成股票/日期、虚构候选、虚拟M0～M8返回模拟接口。原始公司行情、邮件与密钥不进入GitHub。

| 用例 | 输入/操作 | 必须观察到的结果 |
|---|---|---|
| T01 角色加载 | 载入role_manifest与16份Prompt，执行一轮轮转 | 16份文件一一匹配唯一ID；一次episode只注入一份Prompt |
| T02 小预算覆盖 | 一轮中途用尽预算，再开始同campaign下一run | 游标延续，未运行角色不会永久饥饿，顺序在同seed下可重放 |
| T03 能力缺失 | mock仅有分钟Close，无确认行业映射 | 不满足必要分组能力的任务不被派发；原因存run日志，未产生Factor |
| T04 Mask重现 | 相同snapshot/index/seed/概率 | 隐藏group集与view hash完全一致；改变参数时重新产生合法视图 |
| T05 隐藏信息越权 | 对隐藏组按ID点查、全文、关系、论文段落检索 | 生成期M2不返回被遮蔽结论；直接引用也不能绕过过滤 |
| T06 基础事实不遮蔽 | masked下请求原始字段及已发布Daily定义 | 字段/公式/时点始终可见，真实字段不被伪造 |
| T07 全量后验审查 | masked生成与已存在赢家高度类似的候选 | M4/M5查询完整Knowledge，不将遮蔽胜者当不存在 |
| T08 数据版本固定 | M1在episode中途发布新Daily | 本次仍使用旧合法快照；新版本仅在之后合法episode出现 |
| T09 无有效回复 | API超时或返回不合Schema的内容 | 记录调用故障，**不伪造alpha_candidate、Factor或金融失败** |
| T10 注册幂等 | 同一submission_id重发M4请求，第一次响应丢失 | 查回同一个factor_id/experiment_id，不能创建重复Experiment |
| T11 第一关阻断 | 技术/统计FAIL或BLOCKED | M6不被调用，真实金融字段为NULL，阶段及原因记录完整 |
| T12 财务失败 | 两关PASS且M6有效，但Ret或SR未达标 | 保存实际金融指标和financial_fail，不用Score改变资格 |
| T13 并发胜者增加 | 两个候选同时对旧胜者快照初查通过 | M4/M5最新胜者重验或版本冲突处理，不能都绕过相关性硬关 |
| T14 全局恢复 | M4注册后故障、M5/M6中途重启 | 找回已有Experiment和真实阶段，继续合法未完成步骤 |
| T15 Full/Masked配对 | 固定数据/知识/模型/角色预算，仅改变可见性 | 可比较生成结果；正式qualified仍按当时真实M5胜者集合判定 |
| T16 M9暂停 | 运行配置没有经老师批准的遗传策略 | 总编排不自动选父代、不触发进化任务 |
| T17 权限快照 | mask核验例外主动展开一篇隐藏论文章节 | 明确日志记录override，样本不算严格未揭示masked |

## 验收交付要求

- 实测输出以`run_id/episode_id/submission_id/factor_id/experiment_id`为线索，能解释每个阶段是否真正执行。
- 运行日志保留策略版本、可见性视图、工具调用、预算用量与故障原因，且不让研究Prompt获得隐藏组列表。
- 只有M4注册成功才有正式Experiment；只有M6真实执行才有金融指标；M9保持未启用。
- M2/M4/M8与M5/M6使用各自负责的模块测试，不因本文件而修改其固定数学口径。
- 完成合成数据联调不等于真实数据P0问题已解决；实际公司数据上线前必须复核`OPEN_DECISIONS.md`。
