## ① TD008｜多轮 Agent 轨迹拆成单次 LLM 决策，接入常规 RL

**机制位置**：原有 Agent 与工具/环境反复交互，一次任务包含若干次 LLM 调用（期间穿插工具结果）。Agent Lightning 将每次**可训练的 LLM 输入、模型生成输出及奖励**标准化成 `(input_t, output_t, reward_t)` transition；工具输出进入适当的上下文，而非当作模型生成 token 训练。LightningRL 在**LLM 调用层**分配整段任务奖励，再接现有**单次 LLM 调用内部的 token 级 RL**，真正更新所选模型参数。

**辨识点**：把**现有多次调用的 Agent 执行轨迹**与**可复用的单次调用 RL 训练器**衔接，不要求把不同角色、工具结果、所有生成内容硬拼成同一条超长训练 token 序列；不是发明奖励函数、PPO 或 GRPO。**“执行与训练解耦”是支持这种转换的工程组织，暂不额外计一个创新。**

**证据**：原论文 §3.2–3.3、Fig.2–3；§4 的 Text-to-SQL、RAG、计算器任务仅是作者报告的多框架验证，不能说明这种转换方式已优于所有替代训练方式。

**一一对应的不足①**：[IDEAS §1](IDEAS.md)：2025 原论文**实际采用简化的调用间信用分配**：同一执行轨迹中的 LLM 调用分到相同的终端回报 R，然后才交给单轮 RL 算法。犯错的早期调用与纠错的后续调用没有被这一层奖励区分；**不代表每个 token 都被同样更新，也不代表已实证证实训练失效**。更精细的跨调用贡献归因在该论文中仍是开放边界。

## ② TD009｜选择多角色 Agent 中的部分 LLM 调用参与参数训练

**机制位置**：统一轨迹可按 Agent 的**LLM 调用/角色**抽取需要训练的样本，而不是默认训练流程里的全部模型调用。原论文 §4.1 的 Text-to-SQL Agent 使用 SQL Writer、Checker、SQL Rewriter 三种职责，其中选用 **Writer + Rewriter** 的调用做训练数据，Checker 调用不直接进入该训练集合。三个角色可共享同一个底层 LLM、以不同 Prompt 区分职责。

**辨识点**：**选择哪些决策进入参数学习**，不是选择不同模型架构，也不是简单“多 Agent 分工”。能力边界是调节训练数据所覆盖的角色/调用，而非单独冻结未选中角色的模型能力。

**证据**：原论文 §3.2.2、§4.1（Text-to-SQL 案例）。这一实践特征有价值，但**按角色筛选训练调用本身不宣称学术首创**，独立增益也没有被充分隔离。

**一一对应的不足②**：[IDEAS §2](IDEAS.md)：若不同角色共用**同一套底层权重**，Writer/Rewriter 训练引发参数变化后，即使 Checker 没提供训练样本，它再次调用时也会使用改变后的权重，**Checker 的表现不受影响并无保证**。若是多模型角色系统，分开训练也可能忽略角色之间的相互依赖。**作者没有证明 Checker 性能实际下降**；这是从共享参数/协作依赖提出的待核问题。

## 与现有知识的严格语义去重（批准入库前核验）

- **方向 B [TD001–TD005](../../knowledge/DELTA_INDEX.md)**：T001/T002 改写 Prompt、修改策略、反思或搜索分支，**不更新目标模型权重**；T003 通过 Agent 轨迹转换，更新 `θ`。
- **TD006（T005 同权重 Actor/Judge DPO）**：模型**自己评分构造偏好对**再 DPO，侧重奖励/偏好数据来源；本篇使用**外部任务成功反馈并将多次 LLM 调用拆成训练单元**，不自造 Judge 偏好对。
- **TD007（T005 Judge 跨任务迁移）**：关注 IFT/EFT 初始化和回答偏好训练后的**Judge 能力迁移与评价指标变化**；TD009 关注复杂 Agent 中**哪些角色的实际调用被抽作训练样本**，以及共享参数对未选角色的潜在连带影响。都涉及共享权重，但机制所在阶段及证据不同。
- **方向 A [D013/D015/D016](../../../A_alpha_mining/knowledge/DELTA_INDEX.md)**：已有通过市场因子回测结果训练生成模型的 RL，特别 D016 以**整段因子池探索轨迹**生成 GRPO 奖励；不重复称“多轮轨迹奖励更新权重”为新知识。TD008 的差异是**把现有多调用 Agent 的每次 LLM 决策独立映射为单轮 RL transition 的一般接口/学习粒度**。
- **TD008 vs TD009**：前者改的是**训练样本的拆分/信用分配层级**；后者改的是**多角色样本的选择范围**。对应不足分别是**跨调用奖励不细化**和**角色间共享权重/协作依赖**，不是同一句“训练效果不能归因”拆成两条。

**阶段与证据边界**：本次仅批准 T003 单篇特色与不足，不启动方向 B 跨论文阶段二或提出新工程方案；论文 2025 原版的结果属于作者报告，未复现、未证明全球首创。
