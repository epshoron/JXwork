# TD006｜T005：同权重 Actor/Judge 自建偏好对并迭代 DPO

**审批**：2026-10-22 用户批准 T005 特色机制①及其对应特化不足①；这是本项目的机制增量，**不主张首创 DPO、LLM-as-a-Judge 或 AI 反馈学习**。

## 机制指纹：谁、反馈、更新对象

- **输入**：初始 LLM 用人类 IFT/EFT 种子做 SFT 得到 `M_1`；后续采用新的用户任务指令（**主实验由外部固定 Llama 2-Chat 70B 生成**）。
- **具体操作**：同一 `M_t` 执行 Actor 生成 N 个回答和 LLM-as-a-Judge 评分两种角色；最高/最低评分构成 `(指令, chosen, rejected)` 偏好对；用 DPO 微调共享权重，得到 `M_{t+1}`，随后重新生成/评价。
- **真正更新的对象**：**当前 LLM 的模型参数**，不只是 Prompt 文本或外部奖励器。评分模板/训练算法本身并未自动被搜索或改写。DPO 的偏好目标与 LoRA 的低秩微调实现手段是不同层级。
- **输出/实证**：论文 `M_1→M_2→M_3` 同步观察到回答能力与 Judge 指标的部分提升，非无限自进化实证。

## 一一对应的特化不足①

同源 Judge 选出的“最好回答”进入下一轮 DPO，可能强化其原有**长度/格式偏好**。原文观察 AlpacaEval 回复长度平均 **1092→1552→2552**，§6 明确要求进一步研究 length bias 和 reward hacking。**是否真实出现了奖励投机、性能退化尚未被证实**；作者有人类评价和外部 benchmark 改善证据。应在独立外部评估和长度匹配条件下验证。

## 与已有机制严格去重

- **TD001/TD002（Promptbreeder）**：外部自然语言变异 Prompt P/M、成功轨迹衍生上下文，**LLM 权重固定**。本卡把**同模型自评的偏好信号转为 DPO 梯度，更新 LLM 权重**；反馈和更新层级不同。
- **TD003–TD005（GEPA）**：多模块反思 Prompt、Pareto 父代选择/模块合并；不训练基础 LLM 参数。这里不是 Prompt 种群演化。
- **方向 A D013/D015/D016**：尽管同样可能训练权重，但基于公式 TMB、种子因子进化行为或最终因子池评分；**没有本卡“同一生成模型同时给自己产出的普通回答评分、生成偏好对”的奖励构造链**。通用 RL/DPO 不算增量。
- **TD007（本篇）**：TD007 侧重 IFT/EFT **双任务训练带来的 Judge 跨任务迁移及其验证**，本卡侧重**自评分偏好对如何进入 DPO**。避免把完全相同的“共享权重”重复当作两个独立发现。
