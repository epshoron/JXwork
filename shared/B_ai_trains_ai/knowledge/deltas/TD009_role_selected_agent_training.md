# TD009｜多角色 Agent 的选定调用参与参数训练（Agent Lightning）

> **研究者审批：2026-10-22，T003 特色机制② + 对应特化不足②。** 属特定实现/训练组织的项目级特色，不主张“按角色选样本”是学术首次。

## 机制指纹

- **任务/输入**：多角色 Agent 运行轨迹；每次 LLM 调用所属角色及输入输出/任务反馈。
- **操作**：对调用进行**按角色筛选**，仅从特定决策角色提取进入 RL 的训练数据；如 2025 原文 §4.1 的 SQL Writer、Checker、Rewriter 共有三种职责，但只使用 Writer / Rewriter 的调用训练。
- **真正更新对象**：被选中用于训练的 LLM **模型参数**；**不是各角色的 Prompt 或工具代码**。若三角色使用共享 LLM，即使 Checker 的数据没进训练集合，**Checker 下一次使用的权重仍可能已改变**。
- **实验依据**：论文 §3.2.2、§4.1 Text-to-SQL/LangChain，说明训练调用筛选可与现有 Agent 角色划分共存；这本身不是“单独冻结未选角色能力”的保证。

## 对应特化不足②

按角色选择训练**数据**不等于按角色隔离训练**参数**：同一底座模型的共享权重变化可能影响未选中角色，分离不同模型也可能忽略多角色协作依赖。**原文未证明 Checker 已发生性能下降**，相关改进收益归因和负迁移属于待验证问题。[具体疑问与检验](../../papers/T003/IDEAS.md)。

## 与已有机制去重

- **TD008**：抽取单次调用并进行轨迹级奖励→模型 RL 参数训练，解决**训练单元**转换；本卡控制**哪些角色调用**被用于训练。分别具有不同干预位置。
- **TD007（T005）**：涉及同模型 Actor/Judge 的 IFT/EFT 初始化与随回答训练而改变的 Judge 能力，是**跨任务评价能力转移**；本卡关注 Writer/Rewriter 调用是否进入训练及其对未选角色的影响，没有 EFT/Judge 能力任务。
- **TD006（T005）**：同一 LLM 自评选择偏好对做 DPO；本卡没有自评分选择偏好对。
- **[D004](../../../A_alpha_mining/knowledge/deltas/D004_role_separation.md)**：通用生成/审查等 Agent 分工是旧机制；本卡**训练数据的角色级过滤**才是特化更新对象，不能把 Agent 分工本身记成创新。
- **[D016](../../../A_alpha_mining/knowledge/deltas/D016_pool_trajectory_grpo.md)**：为因子池结果训练搜索模型，与这里 SQL 等任务中选定 LLM 调用/角色的数据入口不同；并不重复“参数训练本身”。
