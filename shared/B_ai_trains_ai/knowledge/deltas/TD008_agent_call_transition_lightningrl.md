# TD008｜多轮 Agent LLM 调用 → 单次 RL transition（Agent Lightning）

> **研究者审批：2026-10-22，T003 特色机制① + 对应特化不足①。** 本库的辨识度不等于发明 RL、PPO、GRPO 或 MDP；未独立复现实验。

## 机制指纹

- **任务/输入**：可调用 LLM/工具/环境的现有多轮 Agent 执行轨迹、每次 LLM 的输入/输出、外部任务奖励。
- **操作**：将复杂轨迹里的**每次可训练的 LLM 调用**抽成 `(input_t, output_t, reward_t)` transition；工具数据进入模型下一次输入的上下文，不当作模型生成 token。LightningRL 先将整段任务的奖励分配到 LLM 调用，再通过单轮 RL 算法训练模型输出。
- **实际更新对象**：最终**LLM 模型参数 `θ`**。这不同于进化 Prompt、记忆或 Agent 工作流；Lightning Server/Client 解耦为实现组织，不额外单列机制卡。
- **实际原文边界**：2025 论文的最简跨调用信用分配使用**各调用同一终端回报 R**，并没有证明更精细的调用级价值归因。

## 对应特化不足①

把轨迹拆成决策单元后，若早期调用犯错但后续纠错使任务成功，**统一终端 R 不区分各次调用各自贡献**。这可能影响学习信号的精确性，但**不是已证实整体 RL 失败**；不能和同一调用内 token RL 优势/梯度处理混为一谈。[具体依据与检验](../../papers/T003/IDEAS.md)。

## 严格去重

- **TD001–TD005**：搜索与更新 Prompt/反思/版本父代，不进行模型权重训练。
- **TD006**：自生成答案+同模型 Judge→偏好数据→DPO；本卡是**已有多轮 Agent 中的调用级训练数据拆分**，不依赖自评分偏好对。
- **TD007**：Judge 任务训练初始化/参数迁移，不是执行轨迹→RL transition。
- **TD009**：在 TD008 可抽取的调用中**选哪些角色进入训练**；两者作用于数据的不同维度。
- **[D016](../../../A_alpha_mining/knowledge/deltas/D016_pool_trajectory_grpo.md)**：因子池探索的整体轨迹奖励用于 GRPO 的**金融专项目标**；本卡聚焦**跨 Agent 框架的调用级训练数据接口**，不另开“终端奖励 RL”同义条目。与 D013/D015 共用的参数 RL 基础不称独有。
