# T001｜研究者已批准的特色机制（2026-10-22）

> **范围**：研究者在理解 [通俗骨架](README.md) 后，明确批准下述两组**机制及一一对应的特化不足**。这是**本项目认可的辨识度**，不是论文在全球学术范围内首次发明的宣称；原文实验未独立复现。

## ① TD001｜任务 Prompt 和变异 Prompt 一起进化

**机制的真正变化**：普通 Prompt 优化只搜索任务指令 P；Promptbreeder 把指导如何修改任务指令的 **mutation prompt M** 也作为可变的进化工件。LLM 以 M 修改 P，另一预定义的 hyper-mutation 操作可让 LLM 改 M→M′；**被选择的单位同时携带 P、M**，其适应度取决于 P 在真实训练任务上的表现，因此 M 间接接受下游任务反馈。详见 [TD001](../../knowledge/deltas/TD001_coupled_task_mutator_prompt_evolution.md)。

**证据**：原文 Fig.1–2、§3.1、§3.2.1 / §3.2.3；Appendix B 的 ablation 对比（同时考察初始化方式、超变异与其他操作）。**消融不支持把所有性能增益归功于超变异**；初始化方式的影响尤需区分。

**对应特化不足①**：P、M 的**文本内容**能变，但外层搜索拓扑、二元锦标赛、变异算子选择与外部评价器仍预先固定。即“改进教练的建议”不等于“自动改造整个教学制度”。这是作者 §6 的**明确扩展边界**，不是已证实性能故障。详见 [IDEAS §1](IDEAS.md)。

**与方向 A 的关系**：不同于 [D007](../../../knowledge/deltas/D007_code_evolution.md) 对 Python **因子代码**进行变异/交叉，也不同于 [D017](../../../knowledge/deltas/D017_joint_alpha_metric_evolution.md) 同时搜索因子与**可执行评分指标代码**；这里被联动搜索的是**任务 Prompt P 与其自然语言变异策略 M**，评分规则本身没有进化。普通反馈和多轮遗传搜索不重复单独开卡。

## ② TD002｜成功解答反推任务 Prompt，并更新 Few-shot 上下文

**机制的真正变化**：Lamarckian mutation 根据模型**成功解决某道题时的 working out（正确推理过程）**，调用 LLM 反向归纳一个任务 Prompt。另有 context shuffling 机制维护来自正确解答的 few-shot 示例，使示例上下文与 P、M 一同成为进化个体里的可变对象。两者并非一个算子，而是一组“成功执行经验影响下一代行为指令/示例”的机制。详见 [TD002](../../knowledge/deltas/TD002_success_trace_prompt_induction_context_evolution.md)。

**证据**：原文 §3.2.4–3.2.5、Appendix J.5 和 Appendix B（消融）。训练过程中保存的是**正确任务解答过程**，不是长期跨任务 RAG 知识库。

**对应特化不足②**：作者在 Appendix J.5 的 few-shot 实验**直接观察到**：示例上下文可能主导模型表现，使任务 Prompt 漂移成 `The mutant` / `mutant` 一类无语义文本。由此不能仅凭整个个体的任务分数，断言 P 本身学到了可脱离示例复用的策略；**不等于证明全系统样本外泛化失败**。详见 [IDEAS §2](IDEAS.md)。

**与方向 A 的关系**：与 [D003](../../../knowledge/deltas/D003_success_memory.md) 持久保存**成功因子并按相似度检索复用**不同，这里把**题目的正确执行轨迹**转化为下一代**自然语言任务 Prompt 与 few-shot 上下文**；与 TD001 的“变异算子自身也被进化”不是同一更新环节。
