## 1. 一句话问题陈述与任务边界

CogAlpha 是 **LLM 驱动的新因子（alpha）代码生成和反馈式搜索** 框架；目标是在 OHLCV 数据上产生可运行且具有金融解释的因子，使用预测评价指导突变、交叉与筛选。不是仅从固定因子库中选取因子，也不是直接执行交易的 Agent。之后的 LightGBM/Ridge 模型负责使用这些因子进行股票收益预测，Qlib 回测负责评价组合表现。（§3、§4、附录 B）

## 2. 方法输入、输出和核心机制

- **输入**：股票日频 OHLCV（open/high/low/close/volume）；Agent 专业领域提示；先前生成的有效/无效因子代码和统计反馈。
- **输出**：具备注释/逻辑描述及 Python 代码的可计算 alpha 因子；经筛选的因子集合，进而作为 LightGBM/Ridge 预测模型的特征。不是 LLM 直接给出交易信号。
- **研究探索分工**（§3.1）：七层共 21 个主题 Agent，分别覆盖市场周期、尾部风险、量价、趋势/反转/波动、多尺度、状态门控和复合构造；每个 Agent 根据自己的主题产生候选。分类是**这篇论文内部的任务分工**，不能拿来当整个学科的通用 7 类分类。
- **Diversified Guidance**（§3.2）：对相同方向构建 5 种提示改写（light/moderate/creative/divergent/concrete），促进候选多样性。
- **Multi-Agent Quality Checker**（§3.3、附录 A.3）：Code Quality/Repair + Judge/Logic Improvement 检查代码正确性与金融语义；在受限执行环境做数值/NaN 稳定性检查，并执行面向未来函数的时间泄漏测试；失败则修复或淘汰。**这些是作者的方法设计声明，尚未独立测试泄漏拦截能力**。
- **Fitness**（§3.4）：对候选计算 IC、ICIR、RankIC、RankICIR、MI；论文默认以当代群体第 65/80 百分位确定 qualified/elite，并设最小阈值。合格者进亲本池；精英保留，并在每代继承两个优胜个体。
- **Adaptive Generation**（§3.5）：每代用随机 2 个有效和 2 个最差的无效候选及其理由/分数，形成后续生成提示，令反馈影响下一轮探索。
- **Thinking Evolution**（§3.6）：Mutation Agent 修改一个候选；Crossover Agent 合并两个候选；三种操作为纯变异、纯交叉、交叉后变异。每轮经质量审查再筛选。
- **控制器判断**：系统通过预设的种群选择和评价规则决定谁能进入下一代，LLM 决定具体新代码如何写。所谓「LLM 自主」有清楚的外部评价/流程边界。

**原文主要证据**：[§3.1–3.6](https://arxiv.org/html/2511.18850#S3)。

## 3. 迭代发生在哪里？是否属于 RSI？

- **反馈来源**：可执行性及质量审核结果、预测指标、有效/无效候选的文本分析。
- **更新对象**：下一代因子 Python 代码、种群/亲本池、下一轮提示中的成败案例。
- **机制**：单次研究运行中跨代积累经验（in-context feedback）+ 演化式代码搜索；不是论文已证明的模型权重更新，也没有展示“模型自动重新训练自己的基础模型/算法”的闭环。
- **对 RSI 的定位（研究判断）**：可以称为*固定 LLM 驱动的迭代式因子改进*，但**不宜将其称为严格 RSI 或参数级自我改进**；“Thinking Evolution”是作者赋予的术语，不等于自动实现权重级学习。
- **长期记忆/跨独立任务泛化**：原文展示当前运行的跨代反馈；不足以证明跨任务长期记忆或搜索策略元学习。请勿推断超出论文。

证据：[§3.4–3.6](https://arxiv.org/html/2511.18850#S3.SS4)、[附录 B.6](https://arxiv.org/html/2511.18850#A2.SS6)。

## 4. 评价方式与证据

- **市场/数据**：CSI300、CSI500、S&P500、HSI、HSCI（中国内地、美国、香港）。主实验 CSI300，目标是未来 **10 个交易日**收益；也用 30 日标签作扩展。
- **时间切分（主实验 CSI300/CSI500）**：训练 2011-01-01—2019-12-31；验证 2020-01-01—2020-12-31；测试 2021-01-01—2024-12-01。美股/港股采用不同切分，见附录 B.1。
- **LLM**：默认 `gpt-oss-120b`；因子最终进 LightGBM，另测试 Ridge。初始池约 80，亲本池 32，子代池约 96；每个任务 Agent 默认 24 代，每 8 代为一子循环。NVIDIA H100。
- **预测指标**：IC、RankIC、ICIR、RankICIR、MI（MI 用于质量选择）；回测指标 AER 与 IR。
- **Qlib 模拟交易**：top-50/drop-5 排名策略、按论文文字为**每日**调整且每日最多替换 5 只；开盘价执行；买入 0.05%/卖出 0.15%成本，并有最低每笔 5 元费用。AER=日均超额收益×N；IR=日均超额收益/日波动×√N，N 可为 252；**10 天预测标签不等于 10 天才结算一次超额收益**。
- **主要 CSI300/10 日实验，表 1 原文报告**：CogAlpha IC 0.0591、RankIC 0.0814、ICIR 0.3410、RankICIR 0.4350、AER 0.1639、IR 1.8999。**这是作者实验报告，不是本研究复现结果**。
- **重要细节**：表 1 中 RandomForest 的 RankICIR 0.4385，*高于* CogAlpha 的 0.4350；不能简单说全部 6 项指标均第一（§4.2 作者也注明例外）。
- **消融，表 3**：基本 Agent→加 E（演化）→加 A（适应反馈）→加 G（多样化指导）→加 H（层次领域 Agent），论文提供逐级表现变化；因子种群效果不是仅由“多 Agent 数目”一个变量得出。
- **示例因子**（§4.5、附录 B.9）：初始流动性因子 IC 0.0090、RankIC 0.0061；一次变异下降；继续演化得到 IC 0.0141、RankIC 0.0087。这是机制示例，**不等于每次变异都会单调改善**。

证据：[§4/表 1](https://arxiv.org/html/2511.18850#S4)、[附录 B.1/B.2](https://arxiv.org/html/2511.18850#A2)、[附录 B.3](https://arxiv.org/html/2511.18850#A2.SS3)、[附录 B.7](https://arxiv.org/html/2511.18850#A2.SS7)。

## 5. 三视角标记（必须有机制证据）

- [x] **质量控制**：多 Agent 审核 + 数值稳定性与未来信息泄漏检查；五维因子评分及阈值，证据 §3.3/3.4、附录 A.3。
- [x] **经验学习**：把上一代有效和失败候选的评价/解释加入新 prompt，并据分数进行演化选择，证据 §3.5/3.6；**仅证明提示上下文/种群反馈，不证明 LLM 参数更新**。
- [x] **推理协作**：21 主题 Agent 分工及 4 质量 Agent 的交叉审查，以及突变/交叉 Agent，证据 §3.1/3.3/3.6；**不是 MoE 网络，也没有看到严格意义的 agent debate 对抗辩论证明**。

## 6. 我自己的理解、局限与下一轮核验问题

### 已核实的原文事实

1. 论文研究的是**生成新的代码级因子**，而不是只做因子排序或股票预测；并额外用下游模型训练与回测验证效果。
2. 训练/验证/测试按时间区分，模拟回测考虑了明确列出的买卖费用，不能误称“完全没扣交易成本”。
3. 作者附录 B.6 明确表示结果来自**单次因子挖掘运行**；LLM 随机性会让复现不同，因而没有直接报告多随机种子均值与波动。
4. 官方给出的公开仓库明确注明**仅 prompt 模板，没有运行代码、数据或实验输出**；不能把它说成端到端开源复现项目。
5. 论文局限部分承认全部通过 Qlib 模拟，尚未真实实盘验证（§5）。

### 批判性疑问：不能在未核实时直接定性

- **超参数/大量搜索带来的选择偏差**：24 代 × 大规模候选，如何控制在同一验证期反复筛选导致的研究过拟合？是否有跨时间 regime 的真正前向再验证？（原文未充分化解这一质疑。）
- **跨股票、跨时间的信息隔离**：因子计算用日频 OHLCV，Qlib 于开盘价执行；必须检查 t 日所需的 close/volume 与可交易 t 日开盘的时间对齐。作者宣称有 future-leakage unit test，不等于所有时间对齐和 universe 漏洞都已排除。
- **原始因子正负号与最终模型**：附录 B.9 部分精英实例 *train raw IC 为负*，但预测模型的 test IC 为正；需要澄清因子方向、模型非线性、筛选绝对值是否参与，并避免直接比较 raw-alpha IC 与 model-output IC。
- **代码自主修复的真实成功率**：论文描述审核与修复，但是否报告各环节失败率、误判率、计算开销及二次修复的具体审计？
- **报告结论的条件性**：表 1 RandomForest 在 RankICIR 例外；高排名不自动等于新增可交易 alpha 的因果证明。
- **生成代码的依赖与运行**：部分附录因子调用其他预先生成的 factor 列，后续实际使用时需追踪因子依赖链及是否所有候选都是独立可运行。
- **复现资源限制**：prompt 开源，整体 runtime/数据/实验日志未随之公开；不宜声称“一键复现”。

### 对工程路线的启发（研究推论，非论文证明）

把“LLM 提案/生成”和“客观验证筛选/种群进化”看作两个不同层次的控制权：Agent 负责候选**内容**，固定的外层循环负责候选**存活与探索方向**。它与单 Agent 或多 Agent 并不互斥；今后比较论文时应记录决策控制的归属，以及反馈进入 prompt/记忆/种群/参数中的哪一处。
