## 1. 研究目标：我们要做什么？

从**分钟级（日内）行情与交易信息**中提炼出**每只股票每日可计算的一组特征**，研究它们能否用于日频 Alpha、未来收益预测或其他由老师确认的目标。

核心链路：

**股票 × 日期 × 分钟原始数据 → 清洗/时间对齐 → 日内特征构造 → 分钟到日频聚合 → 股票 × 日期 × Daily 特征 → 时间对齐的验证。**

先分清三件事：
- **数据频率**：例如 1 分钟或 5 分钟行情；
- **特征产出频率**：每只股票每天一个或多个数值；
- **预测和交易频率**：由标签与研究方案另行确定，不自动等于分钟交易或每日调仓。

当前只是根据老师转述形成的工作定义，**不预设必须预测下一天或直接做实盘交易**。这里的「不要求使用 AI」指**原始论文/研报可以完全采用传统统计或金融研究方法**；即使原文不用 AI，其客观金融知识仍可供后续 AI Agent 学习。不能误解为方向 C 与 AI 因子研究无关。

### 与 V1.0.1 的关系：客观金融知识供给

V1.0.1 的 P002 研究路线设想由不同金融专题 Agent 读取分钟级数据，生成逐股票、逐日期的 Daily 特征。方向 C 的文献研究为其**提供可检索的客观金融知识材料**，不是替 Agent 规划或指挥因子搜索，也不修改 V1.0.1 本身。

**每篇材料只整理原文能够支持的内容**：所研究的金融现象、金融假设及其归属、数据字段、时间段、公式/计算机制、作者的解释与检验、结果及适用范围、负结果、局限和证据核验范围。保留原文术语与关键条件，区分「观察结果」「作者假设/解释」「推断」「未验证」。

**知识材料严格中立，禁止加入搜索导向**：不附加面向 Agent 的建议、行动指令、推荐组合、优先级、专家分发意见或自行衍生的 Idea Seeds；不把原论文的某种现象擅自扩写成反转、动量、形态等待生成目标。一个金融机制可能从多个视角被利用，但**由下游 Agent 自己决定理解、联系、组合与验证方式**。资料只用于提供证据，不预先规定 Agent 要产生什么因子。

文献使用 AI 与否、模型复杂与否都不是排除条件；关键是其**可核实的金融内容**。原文尚未验证的结论不得写成已证明规律；没有的公式、数据、结果不自行补全。

### 来源知识类型标签：金融机制与模型架构必须区分（2026-10-27）

方向 C 接收可核实的金融论文与模型研究，但**“来源值得归档”不等于“已获得可解释 Alpha / 金融机制”**。为方便下游检索，**在 INDEX 使用简洁的正式编号：以模型架构为主的论文在数字后加 `A`（如 `C011A`；若核心输入不足，编号优先 `N`，例如 `C009N`），目录名相同；其他保持 `C001` 这类常规编号。第一列不追加长段分类说明，同一数字编号只对应一篇资料**：

- **FIN｜金融现象／统计构造**：来源清楚描述所研究的市场现象、可说明的数据条件、计算定义或具有金融含义的统计假设；**还须区分作者的实证结论与未经证实的外推**。有可计算公式不代表已经验证为有效 Alpha。
- **ARCH｜模型架构／预测实验**：主要贡献在网络结构、学习到的隐含表征、特征压缩或预测比较。模型的**日度输出分数不自动等于可解释的金融因子**，也不能仅从输出唯一反演出真实金融规律。即使能基于模型归因提出候选解释，也必须将归因与可复现、经独立检验的金融假设分开记录。
- **兼有两类内容时可以并列标记**，分类只指本篇**已核实材料的知识性质**，不是质量评级、论文创新审批或下游 Agent 的搜索优先级。

示例：C008N 的核心是分钟**时间下采样**与原始/双路模型的对照；C009N 的核心是分钟区间**字段卷积表征**和日度选股分类，两者均以 **ARCH 为主**（但目前核心输入不完整，编号均优先用 N），不能将 LSTM/CNN 名称本身登记为具有金融含义的 Alpha 构造。C004 的 RV/偏度等明确统计定义更接近 FIN。**不根据表面技术词汇决定 FIN/ARCH；以论文具体对象、公式和经核证据判断。**

### 何时加 `A`：针对论文主知识产出的判定规则

**`A` 不是“出现机器学习算法”的标记，而是“这篇材料主要提供架构/预测实验知识”的标记。** 按原文已核部分回答两个问题：

1. **论文主要在验证什么？** 若核心问题是模型结构、CNN/LSTM/Transformer 等编码器、时间压缩、可学习特征、分支融合或模型预测效果的比较，偏向 **ARCH**。如果核心问题是明确的金融现象、金融假设及其与收益的关系，偏向 **FIN**。
2. **日级产物是什么？** 若关键产物是依赖训练后权重的隐藏表征、预测分数、类别概率，或者只有模型表现对照，**没有作为主要成果独立定义、能讲清金融含义的分钟→日频特征**，则标 **`C00XA`**；即使作者把预测分数称为 factor，也不因此变成显式金融 Alpha。若主要产物是无需依赖某一训练完成的黑箱权重、可明确计算且有金融含义的统计量（如 RV、已实现偏度、订单失衡），并围绕它检验金融假设，则沿用 **`C00X`**。

**不自动加 A 的情况**：论文为了检验或评价一个**明确的金融统计特征**而使用回归、神经网络、GARCH、聚类或其他工具；算法只是手段时，不因为模型名字出现就改号。反过来，单有一个可计算的中间输入（如 RV）也**不足以证明整篇是 FIN**；仍须判断它的主要问题是不是模型预测结构。

**混合论文**：FIN 和 ARCH 事实可在单篇文档同时说明；**编号只按论文主研究问题及主产物选一种**，不叠加 `FA` 等混合后缀。难以判断时，**标注“FIN/ARCH 主类待核”并维持现有编号**，补读原文后再决定；不擅自更改其他 Agent 正负责的档案。类型不是论文质量或盈利能力评级。

**已核样例**：`C004` 研究 RV、偏度等明确统计量及财报事件关系，属 FIN；`C008N` 研究分钟**时间压缩/双路模型**，`C009N` 研究每时段**字段卷积及 LSTM 预测**，两者主要产物是模型表示/预测分数，属 ARCH。**A 表示 Architecture，不表示 Alpha，也不区分 ML 与 DL。**

### 可用数据约束与 `N` 后缀（2026-10-27）

**N = Not directly reproducible with currently expected data（当前预计数据下不能原样复现）**。这是**独立于 FIN/ARCH 的可实施性标记**，不是论文/研报质量等级、不可用知识标签、永久无效结论，也**不改变作者原文实验结果**。当前仅按研究者透露的**暂定**数据边界：每只股票每分钟 **O、C、V、VWAP**；**H/L可能没有，逐笔成交、逐笔委托/订单身份、主动买卖标签、盘口快照均未确认可用**。实际字段一旦核定应重新检查。

**C001–C010 本轮字段核对**：C002N 缺 bid/ask 以生成主回归 MPR；C005N 缺逐笔成交/报价及机构持仓标签；C007N 缺买卖委托序号；C008N 原18维输入缺 H/L 衍生字段；C009N 原11维输入缺 H/L/成交笔数/委托字段。C001、C003、C004、C006、C010 的核心分钟收益或分布构造可用现有分钟收盘价，但并不代表原始清洗、辅助验证与作者实证能完整复现；C006 的指数行情可得性仍待确认。

**何时加 N**：原文主要 FIN 因子或 ARCH 预测模型的**必需输入**依赖当前缺失、而且**不能从已知字段唯一恢复**的交易信息（如逐笔主动买卖、大单订单身份、撤单/挂单量、买卖盘深度、真实分钟 H/L 极值、逐笔报价），导致**原定义或原架构无法直接重现**；在该来源正式编号加 `N` 后缀，论文示例 `C011N`、研报示例 `CR004N`。**只要缺的是可选实验对照、不影响文献主要因子/模型计算，不自动加 N**；数据是否真的缺失不明则先记“可实施性待核”，避免错误标记。

- **能计算相似统计量 ≠ 能复现原因子**：例如分钟 `sign(C−O)` 不等于大单主动资金净流入 `SIGN`，一分钟成交量 `V` 不能区分买卖发起方，也不能从分钟 VWAP 唯一恢复逐笔订单。
- **允许部分利用**：可在客观档案列出哪些条件筛选/统计操作仅需 O、C、V、VWAP，但不要把替代输入的潜在结果归属给原文；`N` 仅表示**主要方法在当前数据下不可原样做**。
- **与 `A` 的关系**：`A` 描述知识主要为模型架构，`N` 描述当前数据不足，是**不同维度**。为了编号干净，若来源同时符合二者，**编号优先标 `N`，ARCH 身份写在单篇正文/状态里，不叠加 `AN` 等复合后缀**。C008N、C009N 经逐项核对原始输入字段后由 A 改 N，ARCH 性质保留；其他材料不能不经检查自动改号。
- **编号管理**：`C001` / `C001N` 只可能对应同一个数字位次，`CR004` / `CR004N` 同理；**Index 第一列永远只放编号链接，编号按数字升序**，类型判定与数据缺口放正文。未来若数据权限改变，经实际字段核对后可修订 N 并同步文档、索引和引用链接。

## 2. 阶段一：先广泛找来源、读懂怎么生成特征

重点寻找**学术论文、券商量化/金工研报**，先看原文或可访问的可靠材料，积累方法与证据，不急于训练模型或提出新架构。

每份资料尽量讲清：

1. **数据是什么**：1/5 分钟 OHLCV、成交额/成交笔数、逐笔成交、盘口还是其他？股票市场、时段、样本范围和可用信息各是什么？不能把分钟 K 线写成真实订单簿。
2. **分钟信息怎样变日频**：全日统计、开收盘分段、指定分钟条件筛选、量价关系、多变量聚合、神经网络时间权重等，具体使用哪些算子或模型？
3. **最终输出是什么**：一天一个统计量、一组因子，还是直接预测分数？有没有进一步的日度平滑、滞后与标准化？什么时候才能实际算出？
4. **关键计算机制**：找原始公式、时段窗口、过滤规则、模型输入输出；优先**自绘一张流程图 + 一个能手算的例子**，解释清楚再谈创新。
5. **如何评价**：预测标签/持有周期、数据切分、IC / RankIC / ICIR、分层收益、衰减、换手、成本以及对原有日频因子的增量；仅记录该来源实际使用的指标。
6. **证据范围**：已读完整论文、部分 PDF、公开研报摘要还是作者宣称？能不能拿到实际公式、图表、附录或代码？不把“做出了特征”写成“已经证实有 Alpha”。

第一轮检索可以沿**高频统计特征、日内时段效应、波动/偏度、量价相关、成交行为、条件聚合、参数化算子搜索、时序模型学习压缩**等角度展开。这只是方便找文献的视角，不是固定类别或已审批的新贡献。

## 3. 研读时尤其要分清的口径

- **避免前视**：全天分钟数据构造的因子通常到当天全部数据可见后才能计算，不能假设盘初已知；标签、交易时点和实际可执行价格要分别说明。
- **市场数据细节**：集合竞价、午休、缺失分钟、零成交、停牌、股票池、复权、涨跌停及生存者偏差，以原文采用的口径为准。
- **不同实验不要混在一起**：日内与隔夜、单日与多日滚动、单因子 IC 与组合增益、作者结果与个人复现是不同层次。
- **不预判复杂模型更优**：简单统计因子、特殊时段/条件聚合、自动表达式搜索和深度学习都是备选研究对象，由证据决定取舍。

## 5. 认领和并行研究（与 A / B 一样）

**实行“每个 Agent 一次只认领一篇、多个 Agent 并行处理不同来源”，不排队串行。** 一个 Agent 完成当前篇的本轮研读、归档及索引同步后，再认领下一篇；不同 Agent 可同时认领不同 C 编号论文或 CR 编号研报，不需要等待彼此。

1. **认领前查重**：刷新本方向 [论文 INDEX](papers/INDEX.md) 与 [研报 INDEX](reports/INDEX.md)，必要时核对 A/B 已有原文。以**原始题名 + DOI/arXiv/研报发布日期和出处**识别同一材料；已有人认领就换一篇，不覆盖他人的档案。
2. **认领即落档**：一篇确定后，取未占用的下一个数字编号；架构类学术论文用 C00XA（A=ARCH），其他论文用 C00X；研报使用 CR00X，当前数据无法复现核心输入时加 N（如 CR004N）；同一工作回合在自己的 `C00X/` 或 `CR00X/` 建立**最少必要的 README.md、PAPER.md**（至少明确真实来源、实际已核信息、未核范围），并更新该类别的 **INDEX**。认领是状态，不冒充已经完成全文研读；后续研究的真实进展继续同步 MD 与 INDEX。
3. **并行写入不互相覆盖**：各 Agent 独立修改自己的编号目录，公共 INDEX 写前重读最新版本与 SHA；如果别人抢先占号或提交冲突，**重新查重、分配可用编号，保留他人的条目并合并后重试**，不能用旧版 INDEX 整文件覆盖。无需其他 Agent 逐个确认或统一排队。
4. **谁处理，谁收尾**：每次新增、修正、撤销或完成当前来源时，Agent 自己在**同一工作回合**更新该篇 MD 与对应 INDEX；知识卡若在认可后发生变动，再同步相应知识索引。不能把同步工作交给另一个 Agent。
5. **来源权限不变但可批量确认**：正式学术论文按可核实原文直接建立客观骨架；券商研报作为非论文材料可先展示候选并请研究者**按批同意收录**。研究者同意后每个 Agent 仍各自认领**一篇研报**，按上述并行流程处理，无须反复逐篇走形式批准。

## 6. 协作方式：参考 A / B，但不把流程做成负担

- **先原文研读、再横向比较、最后考虑我们自己的构造与复现**；当前先做文献和研报调研。一次研究以“看明白机制、数据、算子和验证”为目标，而不是以填满表格为目标。
- 论文经来源核查后，可以归档客观流程与来源，并同步本方向论文索引。**券商研报先把候选、价值和公开可见证据拿来讨论，研究者可按批确认收录**；正式研究结论以可核对的报告内容为准。
- 特色创新、独立不足及机制知识卡要先拿证据来讨论，**得到研究者认可后再正式记入**；对照 A/B/C 防止同一构造被重复包装为不同创新。普通统计量、IC 检验、OOS 或成本约束不自动算创新。
- 每次实际新增、纠正或撤回研究档案，**同时更新对应论文或研报的 INDEX**。仅在对话里讨论，尚未产生可确定的归档成果，就不用频繁改云端文件。
- 遵守既有 [研究协作规范](https://github.com/epshoron/JXwork/blob/main/assistant/AGENTS.md)、[研究计划](https://github.com/epshoron/JXwork/blob/main/assistant/RESEARCH_PLAN.md)、[写作及审批规范](https://github.com/epshoron/JXwork/blob/main/assistant/RESEARCH_WRITING_STANDARD.md)，尽量图先行、言之有据、内容短而清楚。
- 当前 JXwork 为私有仓库，也不应擅自上传公司行情/内部资料/密钥、付费研报全文或缺少再分发许可的材料。

## 7. 接下来需要逐步确定，而不是现在拍板

- 老师到底要**未来 N 日横截面选股**，还是某时点之后的盘中预测或日内择时？
- 手头实际可用的是**分钟 K 线、逐笔成交，还是盘口/委托**？交易市场与股票池是什么？
- 是否先从**可解释统计/条件聚合**开始，再比较可学习的分钟权重和自动化挖掘？
- 是否要交付**文献综述、因子公式库、工程复现结果，或批量化因子生产程序**？

**当前进度以两份实时 INDEX 为准**；本方向仍处于阶段一资料研读，未将任何作者结果当作项目独立复现，也未选定最终技术方案。
