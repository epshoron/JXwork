- **收到研究任务先判所属方向**，读取该方向 README、现有来源 Index 与相关单篇档案；其他方向的相同 DOI/arXiv/相近机制也需查重，不因分目录而重复认领或重复声称创新。
- **本文件下文未带方向前缀的 `papers/P00X/`、`papers/INDEX.md`、`knowledge/DELTA_INDEX.md` 等旧路径，均是方向 A 的历史示例**。执行于 B 时必须替换为上述 `ai_trains_ai/` 的**本方向**路径，不得把 T/TD 误写到 A 的公共 Index。
- 各方向**分别推进**阶段一原文研读 → 阶段二跨论文比较 → 阶段三原创研究设想；A 仍以阶段一研读与单篇评价为主，B 已有 T001 骨架但仍处于阶段一。**仅研究者决定阶段切换**，不能因另一方向已有成果就越级。
- **方向 B 的明确研究问题（2026-10-22）**：上层 AI（可用 CLI 交互）基于知识/记忆与下层 Executor Agent 的任务反馈，自动改进下层 Prompt、Skills、工具路由、记忆检索或工作流；**与之并行研究**通过合成/筛选数据、SFT/RL、蒸馏等更新下层**模型参数**的路线。LoRA 是参数高效微调手段。两条路线都在研究范围，先通过原文和可验证实验比较，**不预先把用户场景定为已验证系统方案**；仅改 Prompt 属外部 Agent 优化，**不是模型权重训练或严格 RSI 的证据**。详情见 [ai_trains_ai/README.md](../shared/ai_trains_ai/README.md)。
- **入库规则**：论文客观骨架经原文核查可归档；非论文来源（包括方向 C 券商研报）先向研究者说明价值，可按批批准收录；创新、特化不足、研究观点和 Delta 经讨论批准并与 **A/B/C** 已有内容去重后正式归档。每次真正新增或修改资料时，同回合同步所属方向的**对应来源 Index**；没有成果变动不机械刷文件。
- 根目录 `README.md`、`AGENTS.md`、`RESEARCH_PLAN.md`、`RESEARCH_WRITING_STANDARD.md` 和 `JXWORK_START_HERE.md` 为**共享导航与规范**；正常单篇研究无需机械编辑它们，协作规则变更时须同步维护。

## 接手顺序

1. 阅读最新 `README.md` 与 `RESEARCH_PLAN.md`，**先确认任务属方向 A、B 或 C，再确认该方向实际阶段**；B 的 T001 2+2 已审，T003 已审 2+2，T005 也已审 2+2，A 仍以原文理解为主。
2. 实时阅读**所属方向论文 Index**，并核对另一方向是否已收录相同题名/DOI/arXiv；已有认领原则上优先交叉引用。**非论文资料在研究者明确批准收录前，不得自行认领、登记、建档或写入任何研究内容。**
3. **必须阅读 `RESEARCH_WRITING_STANDARD.md`**（图先行、语言精炼、特化观察、贡献/缺点研究者审批）；再看**所属方向 Delta Index**；方向 A 可用 `papers/P001/` 作示例、`synthesis/RESEARCH_LENSES.md` 作为 A 专属研究视角；方向 B 参考 `ai_trains_ai/README.md`。必要时查最新 `CHANGELOG.md`。

- **特化缺点绑定具体创新**：研究者要求任何正式缺点评价都要能指出其**对应的论文特色创新/工程设计**及明确的机制性或验证性缺口；多组贡献/不足要逐条配对。设计目标之间有张力不自动成为缺陷；没有可信不足就标暂无，不硬凑。P008 为 D014↔Pass@T、D015↔奖励独立消融的实例。详细规范见 `RESEARCH_WRITING_STANDARD.md`。
- **来源开放，入库有审批**：论文骨架核实后可直接入库；GitHub 仓库、工程实现、实验记录及技术笔记等**非论文来源必须先在对话中讲明与自主因子挖掘/反馈迭代的直接关系，获得研究者明确认可后，才能认领、写索引或归档骨架**。创新/不足仍需逐项审批和严格语义去重。

## 强制同步协议：各 Agent 自己负责（2026-10-21）

**硬门槛：每个 Agent 自己的研究进展，必须在同一工作回合同步自己负责的 Markdown 和共享索引，不能只更改论文文件、不更改 INDEX，也不能把同步留给另一位 Agent。**

1. **开始任务**：读取最新版 `AGENTS.md`、`RESEARCH_WRITING_STANDARD.md`，及**所属方向的论文 Index 和 Delta Index**；同时检查跨方向同源查重与其他 Agent 最新提交。
2. **开始新论文**：A 在 `papers/INDEX.md` 用 `P00X`，B 在 `ai_trains_ai/papers/INDEX.md` 用 `T00X` 认领最低状态；在所属 `P00X/` 或 `T00X/` 完成经核验骨架后，**同一回合更新对应 INDEX 为实际完成状态**。研究者批准创新/不足后，更新该论文的已审 Markdown，**同一回合更新 INDEX**；撤销、纠错和停止研究同理。
3. **更新知识机制**：获得审批且对**两个方向**完成严格语义去重后，新增/修改/合并/撤回 Delta 时，**同一回合更新所属方向的 Delta Index（A：`knowledge/DELTA_INDEX.md`；B：`ai_trains_ai/knowledge/DELTA_INDEX.md`）与相关论文内引用**，确保 ID、审批、证据边界一致；论文研究状态若受影响，再同步 `papers/INDEX.md`。
4. **协作规则变化**：必须同步修改 `AGENTS.md` 和 `RESEARCH_WRITING_STANDARD.md`，并核对 `README.md`、`RESEARCH_PLAN.md`、`papers/README.md` 等入口的指示不相互矛盾。常规论文内容变动不需要无意义地改写 AGENTS，但**每个 Agent 必须重新阅读、遵守最新版**。
5. **结束任务前强制做同步检查**：核对档案与两份 INDEX 的**存在性、链接、审批状态、阅读核验范围和 Markdown 表格格式**；不得丢失其他 Agent 新增行；逐项确认没有漏同步或未经批准内容。**检查或同步未完成，不得对研究者声称“已完成入库”。**
6. **并行保护**：公共文件每次写入前重新读取最新版 SHA；遇冲突重新读取、合并、检查，绝不使用旧副本覆盖其他 Agent 成果。没有实际状态变化的日常对话不刷索引，不建过程流水账。

**权限不变**：只有**论文客观骨架**可核实后自主归档；非论文来源**先获研究者批准才可认领/建档**；所有创新、特化不足、研究想法和 Delta 都必须**先获批 + 严格语义去重**，同步义务不能绕过审批。

## 三阶段先后顺序（不可抢跑）

- **阶段一／当前：完全理解论文本身。** 认真阅读可访问的原始全文及关键附录，回答研究问题、输入输出、具体算法、Agent/搜索器与评价器分工、反馈究竟更新什么、实验怎么安排、结果到底支持哪些主张。尽可能补齐背景、公式、图表、消融和局限；重要判断给出处。仅看摘要、认领论文或空泛概述不算读完。允许记录作者自称的创新与不足，但此时**不进行跨论文创新/缺点整合**。
- **阶段二／以后：整理创新点和缺点。** 在真正读懂足够多论文后，区别原文作者声明与研究者有依据的评判，跨论文比较创新、缺陷、重复和互补性。
- **阶段三／最后：有机结合提出自己的想法。** 在研究积累和阶段二分析充分后，才提出能解决实际不足、能设计实验检验的组合假设及可能研究方案，不机械拼接方法。

项目具体判断、阶段切换标准见 `RESEARCH_PLAN.md`；没有用户明确要求时，不提前启动后两阶段。

## 研究边界

- **方向 A**聚焦 LLM / Agent 因子生成与探索、验证反馈、搜索控制、自主迭代及 RSI 边界，区分因子生成、筛选、预测与交易执行；**方向 B**聚焦上层 AI 基于评测反馈持续优化下层 Agent（Prompt/配置/记忆/工具）及真正模型参数训练（SFT/RL/LoRA 等），具体技术分类与路线优劣尚待核定。
- 先原始证据后判断：优先正式出版方、DOI、arXiv 正文与关键附录；不以二手综述或 GitHub README 冒充已阅读全文。
- 区分候选修改、提示/记忆、搜索规则、模型权重，不能把一般反馈叫严格 RSI。
- **质量控制、经验学习、推理协作**仅是可以共存的理解视角，不是技术流派、研究阶段或能力等级。
- 当前不搭系统、不训练模型、不写 PDF，除非研究者明确提出。

## 多研究 Agent 的轻量去重协议

1. **先刷新所属方向的论文 Index 并检查两方向同源查重**；A 用 `P00X`、B 用 `T00X` 编号，登记真实标题、权威原文链接和最低研读状态。**非论文材料先申请研究者审查其价值，未获明确认可一律不得认领、写索引、建档或上传骨架**；获批后的目录/编号再按研究者确认的方式处理，不提前占位。多个 Agent 协作不靠聊天窗口代号。
2. **只使用共享索引状态去重**，不需要读取其他 Agent 的聊天；认领状态不能写成已读完。各自的研读理解、讨论、纠错都在自己的 LLM 对话内完成。
3. **仅论文骨架无需研究者审批**：核对原始论文后，研究 Agent 可直接将**论文来源、准确自绘架构图、组件与反馈职责**写入 `papers/P00X/`，但仍须在对话中向研究者讲解。**非论文来源须先获研究者批准，连骨架/索引/来源记录也不得提前上云**。任何来源的创新评价、特化缺点、独立想法均须逐项审批并严格去重。不恢复 `notes/`/聊天流水账。
**最高优先级入库门禁**：上传任何贡献判断、特化不足、研究想法或 Delta 前，必须按 [RESEARCH_WRITING_STANDARD.md](RESEARCH_WRITING_STANDARD.md) **逐项进行严格语义去重**，对照最新全库（含其他 Agent 新提交）。同义改写、同一风险换例子、同一机制重复包装均不准另开卡；相似内容先合并/关联，无法证明独立则不提交。**用户拍板与语义去重是两项都必须满足的条件。**

4. **Delta 比对须有辨识度**：读取所属方向的 Delta Index，同时对照另一个方向的机制，只比较能体现论文独特改变的先验、搜索、反馈和更新机制。一般 OOS、成本、市场变化、Agent 分工等不要凑成论文创新与通用缺点。**未获研究者批准的 Delta 仅是讨论草案，不得视为正式知识**。项目首次入库 ≠ 学术首次发明；成熟跨论文综合再进入 `synthesis/`。
5. **状态同步与提交验收**：公共文件写入前获取最新 SHA；冲突后重新读取合并，不覆盖其他 Agent。**每次真实状态变动同回合同步论文 Markdown、**所属方向论文 Index 和所属方向 Delta Index**；结束前按上文强制检查**。减少无实际进度的刷屏更新。
6. 尽量自主阅读公开 HTML/PDF 或作者版本。遇到访问限制，**给出原文链接并如实解释未读内容**，研究者可按需下载 PDF，不应因未上传 PDF 就停止全部研究。

## 安全边界

仓库当前为 **Private**；如改为公开，先重新审查所有文件的版权和访问权限。不得上传公司内部代码、文件、邮件、数据、策略、账号、API Key 或未经许可的论文 PDF。外部模型处理内部信息同样以公司授权为前提。

## 交接时的动作

以当前 GitHub 为准，先按上文选择方向，不假装已读其他研究 Agent 的对话。**每个 Agent 结束一个研究任务前必须核对并完成所有相关 Markdown / INDEX / 规范同步，不得只提交自己的档案**。继续阶段一原文理解；**仅论文骨架经原文核对可自主写入 papers/P00X，仍需向研究者讲解；非论文来源先获研究者批准才有入库资格；创新、特化不足与 Delta 均需逐项批准并严格语义去重**。始终遵守 `RESEARCH_WRITING_STANDARD.md`，不抢跑阶段二/三，不把 Delta 当学术原创。
