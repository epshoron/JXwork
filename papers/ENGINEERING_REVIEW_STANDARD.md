# 方向 A｜工程复现问题速查规范（2026-10-26）

**用途**：P001–P010 及今后方向 A 的单篇工程研究展示。目标是让研究者快速理解论文的实际实现，并可向老师准确说明；本规范只管理“工程问题速查表”，不取代原有 ARCHITECTURE、PAPER、IDEAS、Delta 或三阶段研究流程。

## 1. 每篇怎么做

- **一篇一张简洁主表**，**行数以全部适用问题为准，8–15 行仅为参考而非上限**；三个核心列：`主题｜关键问题｜简明答案`。P001 和 P002 都遵守此规则。不因篇幅删掉可复用问题，也不要拆成几十个端口、密钥、依赖和日志问题。
- **研究者亲自提出的问题一条都不漏**：允许合并近义问题，但答案必须覆盖每一个实际追问（例如“假设从何而来”“输入到Writer的是Prompt还是结构化对象”“显式还是隐式进化”）。
- **特异性是增量，不是全部**：必须先继承所有历史适用问题，再加本篇特色；新增问题还必须反向回补所有既有表。不要机械套固定字段，也不能以短为由遗漏实际问题。
- 普通答案尽量 **1–3 句**，但要写出关键对象与动作，不能停留在“用Agent”“做优化”“会反馈”之类概念性描述。技术词首次出现简要解释。
- 主表**不设**“下一步复现动作”“我的追加问题”“优先级”“证据状态”“源码链接”等多余列；未证实的东西直接写在相关答案中，例如“仅论文描述、源码未公开、尚未运行”。
- **清楚优先，不在“太晦涩”和“太简单”之间二选一**：主表用1–3句写明一个机制的输入、动作、反馈和实际实现，不能只抛“贝叶斯调度”“非负岭回归”等陌生术语。若关键算法无法在单元格讲透，给该篇目录增加**一个可点击的专题图解 MD**：从名字和目标讲起，解释每一步真实操作，给**能手算的教学数字、Mermaid流程图、最少必要公式、论文与开源代码出处及核验边界**；在主表相应单元格末尾加一条详情入口。图解是单张主表的阅读展开，**不是第二张工程表**；不要为每个普通词无谓增建资料。教学例子不得冒充作者实验，简化解释不得改变论文机制。
- **主表坚持一行一项核心机制，不写长名单**：面对 P002 的“七层 21 个 Agent”一类问题，主表只说明**怎样分工、怎样实现**，不在单元格挨个罗列专题。需要展开细节时，在该行末尾放**一个可点击的详情入口**：优先使用作者的权威说明；若有必要梳理和校正原始分类，可在同篇目录增加**一份短 Markdown 补充说明**（如 `P002_AGENT_TOPICS.md`），并在其中逐项链接原始证据。补充 MD **不是第二张表**；同一问题不拆成多行，其他无必要的行不强加链接。

## 2. 贪婪问题复用与双向回溯（强制）

**研究者单篇提出的问题只是该篇的特异性增量，不是该篇的全部问题。工程问题采用“贪婪覆盖”：凡某个问题对另一篇论文有实际意义，都必须在该篇回答。**

1. **问题全集动态扩张**：将 P001–P010 已提出的全部工程问题（含研究者新追问）按语义去重。问题本身可在不同论文里用不同措辞；不预设统一的固定字段、行数或模板，更不擅动 `technical_reading/SCHEMA.csv` 和 `MATRIX.csv` 的零字段占位。
2. **先继承、再特化**：给新论文建表前先读取**所有已建工程表**，把其中对新论文适用的每个问题回答清楚，然后补充这篇独有问题。用户“只问了三个问题”，不意味着新表只能有三行。
3. **新增必反向回看**：任何论文一旦提出新问题，在**同一轮工作**检查所有已建工程表（不仅编号小的，还包括编号更大但已研究的）；只要某篇也有对应机制，立即为该篇补齐。例如 P005 的“单因子分数 vs 池级边际收益”必须回查 P001 的 Main KB、P002 的父代池、P003 的 Alpha Zoo：分别回答到底是不是整池边际筛选。
4. **可对照也算适用**：同问可以得到不同答案。若 P005 真的通过 GRPO 更新模型参数，就要回查 P001/P002/P003 是否有权重训练；若 P005 先用行情生成每日市场文字，要回查其他论文给 LLM 的市场上下文是什么；P001 的“Prompt 如何组装”也应回问其他论文。**不可复制粘贴相同答案**。
5. **只跳过确实不适用**：某篇没有相应工程环节、比较没有研究意义，才可省略。若问题适用但原文/源码没有证据，必须在答案中说明“论文未交代 / 实现未核实”，不能假称不适用，也不能瞎猜。
6. **覆盖优先于篇幅**：之前建议的 8–15 行只是易读的参考，**不是硬上限**。允许把实质相同的追问合并成一行，但不能漏掉任何重点；不为凑数添加端口、密钥、日志、部署排障。
7. **一致性闭环**：新问题入表前查重 → 查所有已建表的适用性 → 本篇与旧篇同步补齐 → 更新所有受影响的 CSV 和 XLSX → 检查问题没有遗失、每篇答案有证据边界。仅工程展示变更不改动已审 Delta/创新/不足或强行刷新论文索引。

**因此：P005 原本的“市场环境、因子池、边际贡献、GRPO”只是一批特异性追问；P005 还必须继承 P001–P003 的底座、输入/Prompt、输出、质量控制、反馈、模型更新边界和公开复现情况等适用问题；新增的池级问题也必须向前反补。**

## 3. 工程追问重点（不是强制字段）

1. **输入与来源**：Idea/种子/知识/因子来自哪里、由谁产生；是文本、公式还是Python代码？
2. **底座与角色**：实际LLM是什么？多Agent是不同Prompt、不同模型、微调还是RL训练？金融专题分别负责什么？
3. **候选生成**：Prompt如何构造？知识库检索后怎么输入LLM？是四路结构化接口还是模板拼接？输出什么格式？
4. **质量与预测**：先查语法/金融逻辑/泄漏还是先做预测评分？谁判定、用什么关键指标和门槛？
5. **迭代、遗传与反馈**：谁负责筛选种群、保留父代和精英？变异/交叉是真正程序操作符还是让LLM根据父代代码写新代码？怎样终止？
6. **多路衔接**：初始生成、持续注入、搜索与进化是交替汇流还是独立并发？只按证据描述，不能臆测线程/并发实现。
7. **自我改进的实质**：究竟改变候选代码、Prompt、外部记忆/种群还是模型权重？有无SFT/RL证据？
8. **源码范围**：公开完整运行框架、仅Prompt，还是只有论文；区分“作者所述”“源码核对”“已实际运行”。

**显式与隐式的准确用法**：这里是解释**工程控制方式**，不是GA教科书的统一分类术语。显式指程序明确定义种群、选择、保留、算子调度等规则；隐式指变异/交叉具体由LLM基于自然语言Prompt和父代代码自行生成，而非预设确定性的AST子树交换。两者可以在同一系统共存。若论文真的使用AST或固定算子，要按具体证据改写。

## 4. 文件位置、审阅与同步

- 一律放在已有论文目录 `papers/P00X/`：`P00X_工程复现问题清单_v1.csv`（**GitHub上直接看**）和同名 `.xlsx`（Excel展示）。**两份保持相同主表内容**，不反复要求研究者下载审阅。
- 工程表是**客观机制速览**，不是独立创新、缺点或Delta归档；任何新的贡献/风险判断仍须研究者先逐项审批和严格语义去重。参考 [研究写作规范](../RESEARCH_WRITING_STANDARD.md) 与 [AGENTS](../AGENTS.md)。
- 只追加真正有价值的新增问题；已有内容优先**原位精简与修订**，不为每轮审阅另建重复文件。若论文研究状态发生实质更新，同回合同步所属论文 INDEX；仅调整展示用表、不改研读状态时不刷 INDEX。
- **公开仓库安全**：严禁写入任何内部网关URL、公司代码、策略、真实数据、API Key或隐私材料。来源级别与运行边界必须如实记录。
- 此规范服务于方向 A，**不自动改变方向 B 的研究路线、审批权限或档案格式**。
