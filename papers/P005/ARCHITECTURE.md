# P005｜已批准的特色机制：因子池轨迹 GRPO 训练

[原文与架构](README.md) · [来源和证据范围](PAPER.md) · [D016 机制主卡](../../knowledge/deltas/D016_pool_trajectory_grpo.md)

## 一句话

**每天让 LLM 多轮生成并测试因子，按对整个因子池的边际贡献增删因子；历史离线训练则把一整条探索轨迹形成的因子池结果当 GRPO 奖励，直接更新 LLM 的搜索策略参数。**

- **工具反馈（当日循环）**：模型提出 DSL 因子 → `factor_evaluator` 计算近期 IC/RankIC 等 → Pool Updater 决定保留/拒绝/替换 → 新的池状态与尝试记录进入下一轮。
- **参数学习（离线训练）**：从同一历史情境生成多条完整工具探索轨迹，用最终因子池的未来窗口 Pool IC/RankIC 计算相对奖励，经 **GRPO** 更新 Qwen3-4B 策略参数。实际测试日不向模型透露未来收益；测试日修改因子池**并不意味着在线更新权重**。
- **审批状态**：2026-10-21 研究者认可“**多轮真实工具反馈 + 因子池边际控制 + 整池轨迹奖励 GRPO 参数训练**”是一项值得记录的 P005 特色机制。**并非认定 RL/GRPO/多轮 Agent 本身首次发明，也非认定采用 LoRA**。

## 对已有机制的实质差异（严格语义去重）

- **P007 / D013**：单因子合法性 + TMB 分组收益奖励，用 DAPO 更新生成策略。**P005** 的训练目标是多轮工具过程后**整个因子池**的 IC/RankIC。
- **P008 / D014–D015**：围绕给定种子因子连续改良，采用多目标进化轨迹奖励。**P005** 维护和替换**整池成员**，用最终池级奖励训练。
- **P002 / D007、P004 / D010**：分别进化代码种群、更新 MCTS 搜索树；P005 还有**LLM 参数梯度更新**。
- AlphaGen 等更早研究已有 RL 因子集合优化，因此 **“RL 训练因子池”不当作学术首创**。本论文值得保留的是上述**整套学习信号与交互组织**。

## 实验与尚未获批的讨论

作者在 CSI300/CSI500 滚动模拟中报告三次运行平均累计收益率 **42.93% / 54.19%**，不是年化收益；与同模型/同 GRPO 的单轮对照在 CSI300 相比，多轮方案高 **7.31 个百分点**（累计收益率）。**单轮 GRPO 对照不能等价为“完全去掉 GRPO”**，尚不足以单独估计参数训练的全部增益。
