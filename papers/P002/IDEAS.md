# P002｜我们的独立思考与候选研究假设

> **仅对 CogAlpha 的可检验问题作备忘**。它们既不是作者已证实的缺陷，也不是我们已完成学术查新的“原创创新点”。仍处于项目**阶段一**；跨论文正式比较与研究方案要等更多证据。

| 候选问题 | 直觉上缺了哪一环？ | 合理的验证方式 | 创新性警告 |
|---|---|---|---|
| **专业 Agent 能否按表现动态分配探索资源？** | 21 个主题有明确先验，但不同市场/阶段的边际价值可能不同；固定预算未必最优 | 控制相同 LLM 调用数；对比固定主题分配、随机分配、自适应预算；衡量**独立** OOS Alpha 数和收益 | 自适应计算与专家路由早有广泛前作，不能说首次提出 |
| **能否把失败反馈结构化并跨任务保留？** | 论文采样好坏候选指导 Prompt，但这不是系统化可检索的失败类型库 | 对比仅示例反馈、失败原因分类库、真正跨任务检索；控制生成成本，量 OOS 质量/重复率 | [QuantAgent (2024)](https://arxiv.org/abs/2402.03755) 已明确有积累成功与失败经验的思想；**简单“记住失败”绝非新发明** |
| **如何确认专业分工带来的是真正新 Alpha？** | 不同角色可能重复制造统计上高分但高度相关的因子 | 代码/AST/语义去重 + 输出相关矩阵 + 增量组合表现；按等量候选比较 | 去重/正则化与 alpha decay 已有研究，如 [AlphaAgent (KDD 2025)](https://doi.org/10.1145/3711896.3736838) |
| **代码时间因果能否审得更全面？** | 禁止未来引用不等于保证 t 日所有输入在成交前已可知 | 自动记录数据可用时间与信号生效时间，强制 next-tradable-time，报告审计前后绩效 | 时间泄漏防范并非新想法；需证明新审计器发现真实漏检类别 |
| **大量进化代数是否导致研究过拟合？** | 每次根据评价筛选和变异，相当于多重尝试 | 严格锁定最终样本外与滚动前瞻测试，研究搜索代数 vs 真正 OOS 效果 | 多重检验、回测过拟合是成熟问题；需要该框架下的针对性证据 |

## 哪些值得以后优先讨论？

**首先**比较“**搜索预算动态分配**”和“**失败原因是否形成可迁移搜索经验**”，因为这两点关乎 Agent 是否真的能改进**搜索策略**，而不只改当前因子。其次把**时间可用性**与**重复搜索的统计偏差**视为更可靠自动化所需的基础验证。

但它们现在都只是**研究问题**。新颖性要看相关论文已有何种机制，效果要靠相同预算、无泄漏、真正样本外的对照实验；不可提前写成项目阶段三的正式新架构。
